## 1. Pre-send bounce challenge = adversarial review WITH fixes

The standard pre-critique review ("review ก่อนส่ง benz dna") is read-only. But when the user signals the draft would get bounced ("ถ้าส่งไปแบบนี้โดน Benz DNA ตีกลับมาแน่นอน"-class challenge), that commissions the fix:

- Run the draft battery with EVERY guard term named in the draft header inside the `--cut` list — a zero-count claimed in the header but never battery-verified is an unverified claim the critic disproves from the body (header says "X = 0", body contains X twice).
- Sweep the predicted bounce points: invented-time markers, constructed mini-story timelines, hidden forks, verdict closers.
- Fix in file, re-run the battery to PASS, PATCH the same Notion page, log the self-review in STATE.

The standard pre-critique review stays read-only; the bounce-warning variant commissions the fix. When the owner asks for the review AND says to state the improvements first ("tell me what you improve before you do it"-class), deliver the critique with from→to fixes READ-ONLY and apply only on an explicit go ("ปรับเลย/แก้เลย"). A one-word owner reply that can name two OPPOSITE actions on the same artifact (กลับ = revert vs ปรับ = adjust) gets a clarify before any file is touched — guessing wrong on a filed draft costs a rebuild round, and a truncated/ambiguous command must never be guessed into an edit.

## 2. Owner-paste import artifacts: strip at import, verify at read-back (recurring on publish pastes)

Owner publish pastes carry rendering artifacts that import into Notion broken; PREVENT both at import instead of repairing the page afterward. Before `replace_content` on ANY pasted publish text: (a) drop bare `> `-only lines (imports as a quote block with ZERO rich_text — a stray empty quote bar mid-post), and (b) strip a leading `# Title` line (imports as a heading_1 duplicating the Name prop — body H1 must stay 0). The archive keeps the paste byte-verbatim — removing an import artifact from the payload is not a text edit. Keep the read-back scan as the safety net: H1 count = 0, and quote blocks' `rich_text` LENGTH (before counting blocks); fallback for anything that still lands = `DELETE /v1/blocks/{id}` (block-level DELETE returns 200 even though page-level DELETE 400s), then re-count blocks. Agent-authored markdown must never carry a trailing `> ` line — a body builder that appends one after each quote creates the same artifact on create. Owner STT style also carries hard-break double-spaces at line ends (seen 10× in one publish) — keep them in the byte-verbatim archive, but rstrip every line when building Notion paragraph blocks or the spaces import as visible junk.

## 3. Dispatch-question duplication

The `>` dispatch question must not restate the H1 title verbatim. A second encounter of the question should fork toward the post's real tension (first names the phenomenon, second splits its cause); a verbatim repeat reads as padding to the critic.

Verify with an equality check between the title line and the quote line before filing; make this part of the standing battery. Two data points say this is an OWNER CALL, not a hard rule: the critic froze the duplication as a defect once, and the owner deliberately kept both in a later publish — so flag the match to the owner at draft time, and record a kept match as an owner-call NOTE in the corpus entry; never silently ship or silently cut.

## 5. Battery pronoun lookalikes — fix the counter, not the grade

The battery's Thai pronoun counts are APPROXIMATIONS, never the grade itself — verify in code by LISTING every occurrence with context before grading, and log BOTH numbers (counter vs eye) in the grade header every time. Both known defects have now recurred, so the counter output is untrusted until the script is fixed: (a) overcount — `คุณ` counted inside `คุณค่า`/`คุณภาพ` (lookalike nouns), and `เพราะ`/`พร้อม`/`พรีวิว` inside the พร count (counter 6, eye 0 on a fresh class-level draft — Thai-Latin hybrid words like พรีวิว are พร-lookalikes too; list every hit with context and grade the eye number); a count entirely inside a lookalike family is a DECLARED zero, not a violation. (b) undercount — the lookahead `(?![ก-ฮ])` drops พร+verb compounds (พรปล่อย/พรเลย/พรรับรู้ → reported 1, eye 3) and เรา compounds (reported 2, eye 6); two occurrences and it systematically skews pronoun-register grading. Fix both in the repo script `skills/content-pipeline/scripts/draft_battery.py` at the next repo touch: คุณ needs the Thai negative lookahead, พร/เรา need consonant-compound awareness (lookahead alone cannot separate พร+กริยา from lookalikes). Draft-time prevention beats grading around them: write sentences so they avoid the lookalike families (เพราะ/พร้อม near พร; คุณค่า/คุณสมบัติ near คุณ — usually a one-verb rewrite), and put those families in the battery `--cut` list as declared zeros so the pronoun counts run clean instead of needing an eye-audit. Third recurrence confirmed: `--cut`-listing เพราะ silences the CUT scan but the SEPARATE pronoun counter still reports พร ×7 (all seven inside เพราะ) — the two passes do not share the --cut list; the only clean path is eye-audit every hit → declare the family as FP in the draft header → rerun the battery with the family dropped from --cut so the grade log reads PASS against the declaration. Use draft_battery.py as the ONLY measuring instrument for wc-w/pronoun/CUT numbers — a hand-rolled word regex drifts several words from the script on the same text (99 vs 103 measured back-to-back), and a ratio computed from a hand count ("1.17×") is a guess wearing a measured number's clothes. And RUN the measurement before writing any grade header: archive/corpus headers pre-filled with wc-w, pronoun, or '?' numbers before the battery/census ran have shipped wrong twice (a guessed 2.75× that was really 1.07×, a guessed '?' count that was 0) — write "measured in code" placeholders, then fill the real numbers from the run output, then diff the header against the run before committing.

## 15. Content Drafts DB create mechanics: props schema, token path, parse order

File a fresh draft with POST /v1/pages (parent = Content Drafts DB `3ccdf8d8-8d8c-81ae-bdf8-cb9eb1821520`), after a slug-check query on Name-contains returns 0 exact matches. Send the body as the TOP-LEVEL `markdown` param alongside `properties` — a block-level markdown type does not exist (`children:[{"type":"markdown",...}]` 400s validation_error listing embed/bookmark/image/...), and `children` must never be combined with `markdown` in one body. The search endpoint returns LOOKALIKE-title hits (a shared substring like เก่ง matches sibling titles) — the duplicate test is an exact-Name match among hits whose parent = this DB, not a zero-hit count. Prop types that the API enforces: Name = title, Topic = rich_text, Status = select ("draft"), Date = date, Platform = multi_select — sending Platform as rich_text fails with 400 (multi_select is the type, no fallback shape exists), and the status-typed form `{"status": {...}}` also 400s on this workspace's select-typed Status ("Status is expected to be select"). On a page UPDATE, a combined multi-property PATCH can 400 on a field that each property PATCHed ALONE accepts — when a props update 400s, split it into one PATCH per property (Name, then Status, …) before restructuring the payload. Read the token from `~/.hermes/.env` (NOTION_TOKEN or NOTION_API_KEY); the repo-copy token path noted in older state files does not exist.

**Table blocks on create/rebuild (pair #103 recipe):** typed-block builders do NOT convert markdown `|`-tables — a pipe-table in the payload lands as raw pipe-text paragraphs; build the table as an explicit typed block: `table` requires `table_width` + `children` present in the SAME payload (omit `children` → 400 "table.children should be defined"; a table is one of the block types that CANNOT be appended childless), each child = `{"type":"table_row","table_row":{"cells":[[richtext,...],...]}}` — each CELL is an ARRAY of rich_text objects (a single object instead of a list 400s "cells[0] should be an array"). A plain `table` shell via PATCH /blocks/{page_id}/children gets REJECTED when its `children` key is missing, so the two-step shell→rows route does not exist for create — use the `"after": <anchor_block_id>` body param on PATCH /blocks/{page_id}/children to land the table mid-page (a query-string `after` 400s; the anchor is the heading the table belongs under). RE-INSERT HAZARD: a retry after a partial failure duplicates table rows silently (8 rows became 16 on pair #103) — after any table insert, GET /v1/blocks/{table_id}/children and assert the row count equals the source table's row count before closing; DELETE the surplus rows (block DELETE = 200).

Parse order for agent-authored drafts: strip the `<!--...-->` header and leading blank lines BEFORE reading the title line. The top-level `markdown` param RENDERS markdown — a `# Title` line inside the payload imports as a heading_1 BLOCK duplicating the Name prop (reproduced 2026-11-04 on create; the read-back H1 scan caught it; fix = DELETE the heading_1 block, read-back census returns to plan) — strip the H1 line from the markdown payload itself, do not rely on the block builder's filter. Recovery is delete-all + rebuild on the same page + PATCH Name (the create cannot be partially patched back to clean). Platform multi_select takes OBJECT form (`[{"name":"general"}]`) — bare strings 400 validation_error. Typed-block children work on the CREATE path too (not only lesson 25's rebuilds): derive blocks from the stripped body with lesson 25's builder and POST them as `children` — quote rich_text carry `annotations.bold:true` at build time, so the bold-drop pitfall (which is markdown-import-specific) never applies and no per-block PATCH round is needed; read-back `annotations.bold=true` confirmed. The DB object exposes its schema under `data_sources[].id` (`GET /v1/data_sources/{id}`). `POST /v1/databases/{id}/query` WORKS with an empty-body `{}` — what 400s is `page_size` in either the body or the query string; duplicate checks still go through the search endpoint (its lookalike-title rule below still applies). ## 23. Idea-only briefs: spine = a verb-metaphor over the brief's own model — with drafts-side insight-once and universal-negative checks

An idea brief (a reported phrase + the author's mental model + a number — NO event, NO scene) still drafts class-level in CURRENT FORM; the recipe that files clean first-try:

- Keep every quoted phrase REPORTED ("คำนิยามที่แถมมาด้วยคือ…") — the brief's judgment words (e.g. "เข้าใจผิด") are never asserted as fact; reframe them as the BOUNDARY of the reading (อ่านได้กับงานชนิดที่เคยเห็น).
- The brief's mental model (a line/spectrum) stays THE AUTHOR'S map, framed "ถ้าวาง…เป็นเส้นตรง" — never a fact about the domain; a number with no measurement behind it gets QUESTIONED, not asserted ("ตัวเลขนี้วัดที่ไหน" — the observation that nothing measures it IS the post's content).
- Compress the insight to a verb metaphor (a skill "ถูกอ่าน"), title = that phrase + a tension clause, never a how-to promise; with no event to end on, derive the duck closer from a SECOND facet of the spine (where the number lives / what the model leaves out) so the insight lands exactly once (rule 48 applied at draft time, not only in freeze rounds).
- Hunt universal negatives at draft time ("ยังไม่มีใครเห็น…") → replace with the IMAGE that implies it ("จุดที่วาดขึ้น ไม่ใช่จุดที่มีคะแนนรออยู่"); cut preemptive-defense sentences ("X ไม่ได้ผิดในตัวมันเอง") keeping the function with a positive phrasing ("X ยังบอกอะไรได้จริง").
- Build the battery `--cut` list by harvesting the declared Guards/CUT lines of the recent sibling headers in `posts/` (closest pairs first), not from memory.
- End the body with the hashtag tail (default trio + topic tags after a lone `.` beat line) BEFORE filing — the battery has no hashtag-presence check, so a draft without it passes every scan and still reads as unfinished to the owner (lesson 32).

## 24. Read-back closes only on a RECONCILED scan — a mismatch vs the file battery = dump every block

## 25. Rebuild mechanics on an EXISTING filed page: the `markdown` param is create-only — append explicit blocks

A re-spine/rewrite round rebuilds the filed page in place: DELETE every existing block first (block-level DELETE returns 200 even though page-level DELETE 400s), then append via PATCH /v1/blocks/{page_id}/children. The top-level `markdown` param that works on POST /v1/pages (lesson 15) is CREATE-ONLY: a children payload carrying `{"type": "markdown", ...}` 400s validation_error (the error lists embed/bookmark/image/...). Because the delete lands first, a failed append leaves the page EMPTY — append the real content immediately in the same round and verify before closing; never leave a filed page half-rebuilt.

Use the HTTP method PATCH itself in curl (`-X PATCH`; a POST on the same URL returns `Invalid request URL` — the method, not the path, is the failure). The append endpoint has ONE verified form: `/v1/blocks/{page_id}/children` (with `"after"` for mid-page inserts, lesson 29; WITHOUT `after` = plain end-append — fine for full rebuilds). `/v1/pages/{page_id}/children` is NOT an endpoint — reproduced `invalid_request_url` 400 on 2026-11-04 after an earlier session recorded it as "verified"; the block-level DELETE that preceded that failed append had already emptied the page, so the false note cost a rebuild with the page sitting empty — always run delete AND append in the same working session and re-verify read-back before doing anything else. Build the children as EXPLICIT block objects from the stripped body (header + title line removed first): blank lines filtered at build time; `### x` → heading_3, `## x` → heading_2 (the duck closer stays heading_2; H1 never enters the body); `> **x**` → quote whose rich_text are ALL annotation bold; a `**x**`-wrapped paragraph → paragraph with all-bold rich_text (strip the markers from the CONTENT string — typed rich_text does not parse emphasis, so a `**` left in the text ships literally beside bold:true and fails the marker-free read-back); a `*x*`-wrapped paragraph (owner WEB-style italic subtitle) → paragraph with all-italic rich_text — check italic BEFORE the bold rule or the `**` startswith test misroutes it; for TECH posts special-case the duck closer so its intentional `#` prefix survives (`#สรุปแบบวิศวกรเป็ด` is a plain `#` H1 by TECH spec — a generic heading conversion strips it; assert the `#` in the read-back); everything else a plain paragraph. A `---` hr line in a publish paste is a web-render artifact: skip it (no divider block), keep it in the byte-verbatim archive. Verify the result by block-type CENSUS first (Counter over each block's `type` — heading/quote/paragraph counts), THEN the marker/bold/CUT scans: a dump script's own label prefixes (printing `[H3]` for what the API returns as `heading_3`) can filter real blocks out of the visible output and fake a missing-marker result. Close with the Status PATCH (draft stays draft on pre-critique rounds; rewritten after a critique-driven re-spine).

Insert-after and wrong-nest mechanics (extends lesson 29's table conversion): PATCH `/blocks/{block_id}/children` appends NESTED UNDER that block, never as siblings — an append to a paragraph returns 200 while burying every added block one level down, and a top-level read-back then false-reports all the new markers as missing (32 blocks "lost" this way once; they were alive but nested). To insert after a block at page level, PATCH `/blocks/{page_id}/children` (a page is a block) with `"after": <block_id>` in the JSON body (a query-string `after` 400s; `/pages/{page_id}/children` is not a valid URL at all — see above). Repair a wrong nest: GET the nested children, rebuild each as a plain typed block (type + rich_text only — API returns more fields than create accepts), append to the page with `after`, DELETE the nested originals (block DELETE = 200), then close on a fresh top-level read-back with full marker checks and an empty-block scan (0 empty paragraph/quote blocks) — and PATCH the page's `Updated` date property when the page carries one.
