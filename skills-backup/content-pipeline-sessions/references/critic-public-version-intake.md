# Critic-authored public version intake + bot-seed evidence (lessons 66–67)

## 66. Mentor-authored public version lands on the drafts pair — file verbatim, audit only

When the owner forwards a critic-side rewrite/public version (the critic produced the article text; the gate answer arrived with it), the round is INTAKE onto the existing pair, not a new draft:

1. Archive BOTH texts verbatim first — the critique (gate answer recorded in its archive header) and the outgoing draft version it replaces. Read_file the live posts copy before overwriting: across compactions the in-context copy goes stale and the overwrite is refused mid-flow, costing a retry round.
2. File the public version on the SAME pair page with the typed-block builder: the critic's chosen title becomes Name, H1 stripped per the standing import rule, the two-tier public shape preserved (subtitle as heading_3, duck closer as heading_2), and bold-lead lines (`**lead** — rest`) parsed into two-span rich_text (bold lead + normal rest). Multi-line stanza paragraphs import as one paragraph per non-empty line — the public form is line-per-sentence (lesson 12).
3. Run the battery as an AUDIT ONLY — put the numbers in the header and the reply, but never silently edit the mentor's text and never offer register fixes unprompted: the mentor's text is the deliverable under the owner's gate, and an agent edit forks the authorship the owner expects to publish. A lone `?` FAIL on this text is lesson 9's web-standard artifact — log, don't grade.
4. PATCH Status → rewritten (delegated-rewrite mechanics — the deliverable is a version awaiting owner review, never self-published).
5. Record the register delta in the draft header (a public version typically shifts from the พร-narrated personal register to a เรา-carried universal one) — the owner chooses which register ships.

## 67. Bot-seeded personal anecdotes are unconfirmed evidence — flag before Benz, resolve on owner word

When re-skinning an external-model draft, any first-person event in it may be the BOT's story seed, not the owner's life; a critique round run on an unconfirmed event grades fiction and its keys attach to nothing real. Draft-time gate: carry a STORY SEED NOTE in the header listing seed-originated events as pending owner confirmation, and surface it in the pre-send report. On the owner's correction (usually a swap to the real case in a domain the owner actually lives in), swap the case and mark the note resolved — the argument structure survives the case swap, so rewrite the case paragraphs, not the spine.

Provisioning side: the owner-voice identity pack for external bots lives in `rakazo/kit/phon-identity.md` (repo) — ordered reads (SOUL → thinking playbook → repo SKILL.md via `sed` line ranges, never a whole-file read of a megabyte-scale skill → ≤4 real corpus posts → 1 critique pair); the corpus is register calibration, never a copy source, and the bot's mount is read-only.
