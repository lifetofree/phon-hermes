# E-Book Playbook — สูตรมาตรฐาน "คู่มือฉบับลงมือทำ" ของบ้าน

> สกัดจากเล่มจริง 4 เล่ม (Google Workspace Guide / Hermes Installation Manual / Notion MCP Guide / Local Installation Guide — ผลงานชุด autoclaw พ.ย. 2026) + บทเรียนจากความล้มเหลวของ flow เดิม (เล่ม "คู่มือติดตั้ง Rakazo" 17–20 พ.ย. 2026 — ทำไม่จบ)
> เล่มถัดไปทุกเล่ม: fleet ทำเองตาม playbook นี้ — พรแตะ 2 จุดคือ อนุมัติ outline + ตรวจจบเล่ม

## 0. กฎเหล็ก (บทเรียนจากความล้มเหลว)

1. **1 เล่ม = 1 งานจบ** (Google Workspace, การติดตั้ง, MCP — อย่ายัดหลายวิชา)
2. **โครงบท = TEMPLATE ที่ใช้ซ้ำ ไม่ใช่ HTML mockup ล็อกหัวข้อ** — ห้ามล็อกหัวข้อ/งบหน้าก่อนมีเนื้อ (สาเหตุแก้บรีฟ 6 รอบ 2 วัน แล้วตาย)
3. **แหล่งอ้างอิงทางการ = source of truth เดียว** — รวบรวมไฟล์ docs ทั้งหมดก่อนเขียน ห้ามมี 6 เอกสารตั้งกฎซ้อนกัน (บรีฟ+DIRECTIVE+addendum+mockup = สูญเสีย 4 วันเปล่า)
4. **ห้าม QC มนุษย์รายบท** — QC ตัวอย่าง 3 บทแรกครั้งเดียว จากนั้น QC อัตโนมัติ จบเล่มค่อยส่งพร
5. **เสียงคู่มือ ≠ เสียงบทความ** — คู่มือพูดกับผู้อ่านว่า "คุณ" ไม่ใช่เสียงพร (บทความใช้เสียงพร, คู่มือใช้เสียงคู่มือ — ห้ามผสม)
6. **ทุกคำสั่งต้องมีที่มา** — "คัดลอกมาจาก docs ทั้งหมด ไม่ได้แก้" แบบเล่มจริง ห้ามแต่งคำสั่งเอง (Benz DNA: ตรวจสอบได้)

## 1. สเปกเล่ม (จาก 4 เล่มจริง)

- ความยาว: **3,900–6,800 คำ** (ไม่ใช่เล่มใหญ่) · 10–11 บท
- ปก: ชื่อผลิตภัณฑ์ + <TYPE> GUIDE + "คู่มือ<X>ฉบับลงมือทำ" — ไทยตัวใหญ่
- เสียง: ไทย + ศัพท์เทคนิคอังกฤษตรง (ไทย ~65%)
- ท้ายเล่ม: **COLOPHON** — แหล่งอ้างอิงไฟล์ต่อไฟล์ + license + ข้อจำกัดความรับผิด + "ตรวจกับไฟล์จริงอีกครั้งก่อนใช้งาน" + ฉบับ/เดือนปี

## 2. โครงบท TEMPLATE (ใช้ซ้ำทุกบท)

```
CHAPTER
NN
<ชื่อบท 2 บรรทัด: หัวข้อ + คำสัญญาสั้น>
<นิยามเปิด 1 ย่อหน้า>
[เป็นบท concept] เปรียบเทียบให้เห็นภาพ — analogy ใกล้ตัว 1 กล่อง
[เป็นบท concept] สามคำที่ต้องแยกให้ออก — glossary 3 คำ
[เป็นบท concept] หนึ่งคำสั่ง เดินทางอย่างไร — flow 01–05
[เป็นบท hands-on] ภาพรวมของสิ่งที่กำลังจะเกิดขึ้น — 01–04
[เป็นบท hands-on] ขั้นที่ N — <verb phrase>
  → TERMINAL box + ที่มาคำสั่ง ("ยืมจาก docs แบบไม่แก้")
  → กล่อง "สิ่งที่คำสั่งทำให้" + กล่อง "ถ้า X สะดุด" (troubleshooting ในบท)
หน้าล่าง: บทที่ N · ชื่อบท | หัวบน: บทที่ N / <BOOK NAME>
```

## 3. FLOW การผลิต (fleet เวอร์ชัน)

1. **PL รวบรวมแหล่ง** — docs ทางการไฟล์ต่อไฟล์ (ลิสต์เก็บไว้ทำ colophon) ยืนยันว่าครบประเด็น เขียน scope 1 ประโยค "เล่มนี้สอนอะไรจบไหม"
2. **PL ออก outline 10–11 บท** — ชื่อบท 2 บรรทัด/บท ตาม template §2 — ส่งพรอนุมัติ (จุดแตะที่ 1)
3. **AW เขียน 3 บทแรก** (เปิดเล่ม + concept + hands-on แรก) — ใช้ template + แหล่งเดียว
4. **พรตรวจ 3 บท** เสียง/มุม/ความลึก — ครั้งเดียว (จุดแตะที่ 2) → ล็อก voice-guide บทคู่มือ
5. **AW ยิงบทที่เหลือต่อเนื่อง** ไม่หยุดรายบท — ทุกบทผ่าน **QC อัตโนมัติ**: checklist Benz DNA (ที่มาคำสั่งครบ/ไม่มีคำเกินจริง/เงา AI = 0/กล่อง troubleshooting มี) + ตรวจคำสั่งแต่ละอันย้อนกับ docs จริง
6. **รวมเล่ม + COLOPHON** + QC รวม (ความสม่ำเสมอ template/เสียง/คำศัพท์ ทั้งเล่ม)
7. **พรตรวจจบเล่ม** (จุดแตะสุดท้าย) — แก้จบรอบเดียว publish

## 4. Checklist QC อัตโนมัติต่อบท

- [ ] โครงตาม template §2 ครบทุกบล็อกที่บทนั้นควรมี
- [ ] ทุกคำสั่ง/ตัวเลข มีบรรทัดที่มา (ไฟล์ docs + วันที่ดึง)
- [ ] เสียง "คุณ" ตรงทั้งบท (ห้ามหลุดเสียงพร/เสียงบทความ)
- [ ] กล่อง troubleshooting ครอบจุดพังที่พบได้จริงในขั้นนั้น
- [ ] ไม่มีคำเกินจริง / สัญญาณ AI (—, วงเล็บแทรก, สามข้อสรุปซ้ำ)
- [ ] คำศัพท์เทคนิคสะกด/ใช้ตรงกับ docs ต้นทางทั้งเล่ม

## 5. ข้อห้าม (จากซากเล่มที่พัง)

- ห้ามอ้างเล่ม/ผลงานคนอื่นเป็นแหล่งเนื้อหา (format ยืมได้ เนื้อหา/ปรัชญาห้าม)
- ห้ามตั้งจำนวนหน้า/บทจากเล่มเทียบ — ให้เนื้อหากำหนด
- ห้ามแต่งคำสั่ง/ตัวเลขที่ docs ไม่มี — เว้น [รอพรเติม] แทน
- ห้ามเปลี่ยนมุมเล่มกลางทางโดยไม่ผ่านพร (มุม = ตัดสินที่ outline รอบเดียว)
