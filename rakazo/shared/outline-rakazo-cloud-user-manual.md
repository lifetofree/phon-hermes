## โครงเล่ม (เป้าหมาย 42–50 หน้า A4, 6 ส่วน + ผนวก 5 ชิ้น)

### ส่วนที่ 0 — ก่อนเริ่ม (หน้า 3–8)
- **0.1** เล่มนี้สำหรับใคร / ไม่ใช่สำหรับใคร
- **0.2** เลือกทางให้ถูก: **Rakazo Cloud vs รันเองในเครื่อง (Docker) vs เช่า VPS** — ตาราง 3 คอลัมน์ + ใครควรเลือกอะไร
- **0.3** ต้องมีอะไรบ้าง: อีเมล · บัตร (ทดลอง 7 วัน) · โมเดล (เครดิต หรือ API key ของตัวเอง) · ไม่ต้องมีเครื่องแรง
- **0.4** ศัพท์ 8 คำ: Bot · Chat · Routine · Approval · Computer · Credit · Space (พื้นที่ทำงาน) · Workspace
- **0.5** อ่านยังไง: 3 เส้นทางลัด (อยากได้บอททำงานให้ / อยากให้บอทต่อแอป / อยากคุมค่าใช้จ่าย)

### ส่วนที่ 1 — เปิดใช้ครั้งแรก (หน้า 9–16)
- **1.1** สมัคร & เลือกแผน: Standard $15/mo ($12/ปี) · Pro $49 · Max $99 + เครดิตตั้งแต่ $20/mo · bot computer รวมในแผน (15 ชม. เดือนแรก) — ตารางค่าใช้จ่ายจริง
- **1.2** Sign in ครั้งแรก + เลือกโมเดล: ใช้เครดิตของ Rakazo vs ต่อ API key ของตัวเอง (Claude/OpenAI/อื่น) — ตารางเปรียบเทียบ
- **1.3** สร้างบอทแรก: พูดภาษาธรรมดา (ตัวอย่าง prompt จริง 5 แบบ) · บอทจะถามสิ่งที่ขาดเอง
- **1.4** รู้จักบอทของคุณ: ความจำระยะยาว · ที่เก็บแชท · ที่เก็บไฟล์ · ทำไมบอทแต่ละตัวไม่เหมือนกัน
- **1.5** ลอง 3 อย่างในวันแรก: สรุปข้อความ · ค้นหาข้อมูล · เขียนฉบับแรก (พร้อม "ผลลัพธ์ที่ดูดี" เทียบ)

### ส่วนที่ 2 — ให้บอทต่อกับแอปที่คุณใช้อยู่ (หน้า 17–26)
- **2.1** หลักการ: ต่อแอป = บอทเข้าถึงข้อมูลคุณ → อนุมัติ sign-in ครั้งแรกเสมอ · ตรวจว่าใครอนุมัติ
- **2.2** Gmail (อ่าน/ค้น/ส่ง) · Slack · Notion · GitHub (+1,400+ integrations) — ทีละแอป หน้าละ 1 หน้าจอ
- **2.3** จัดการสิทธิ์: ให้สิทธิ์น้อยที่สุด · ถอนสิทธิ์ · ดูว่าบอทเข้าถึงอะไรได้บ้าง
- **2.4** ข้อควรระวัง: อย่าให้บอทแตะบัญชีธนาคาร/ระบบที่ทำงานจริงตอนแรก · อย่าให้บอทใช้คอมพิวเตอร์ที่คนอื่นใช้ร่วม

### ส่วนที่ 3 — ให้บอททำงานเป็นนายเอง: Routine (หน้า 27–35)
- **3.1** Routine คืออะไร (พูดประโยคเดียว เช่น "ทุกวันจันทร์ 8 โมง สรุป inbox ให้") + 3 ตัวอย่างที่ใช้จริง
- **3.2** ตั้ง routine: เขียนคำสั่ง → ตรวจเวลา/โซนเวลา → ดูว่ารันเมื่อไรและผลเป็นอะไร
- **3.3** คอมพิวเตอร์ของบอท: ทำอะไรได้ · นับชั่วโมง · คิดเงิน · พักเมื่อ idle
- **3.4** ปลดล็อกพลังบอททีละขั้น (approval ladder): อ่านก่อน → ให้ร่าง → ให้ส่ง → ให้ทำเอง (แผน 5 วัน)
- **3.5** แก้เมื่อ routine ทำผิด: สั่งแก้จุดเดียว / ปิดชั่วคราว / ลบ

### ส่วนที่ 4 — ใช้จากที่ไหนก็ได้ (หน้า 36–39)
- **4.1** เว็บ (app.rakazo.com) — ครอบจอ 4 จอ
- **4.2** Desktop app: ครั้งแรกให้เลือก server (Cloud / local Docker / existing instance) + โหมด "ใช้คอมพิวเตอร์เครื่องนี้" (พร้อมคำเตือน)
- **4.3** มือถือ: อ่าน/ตอบ/อนุมัติ · push notification
- **4.4** คุยต่อจากที่ไหนก็ได้: ประวัติแชทเดียวกันทุกอุปกรณ์

### ส่วนที่ 5 — ดูแลระบบและค่าใช้จ่าย (หน้า 40–47)
- **5.1** เครดิตโมเดล: นับอะไร · หมดแล้วทำอย่างไร · ตั้งงบไว้ก่อน
- **5.2** ชั่วโมงคอมพิวเตอร์: นับยังไง · แผนต่างระดับ (4/8 vCPU, RAM, จำนวนชั่วโมง)
- **5.3** ความปลอดภัย: องค์กร/สมาชิก · audit log · ปิดบอท · ลบบอท · ถอนสิทธิ์ทั้งหมด
- **5.4** แก้ปัญหา: ตาราง "อาการ → สาเหตุ → แก้" 20 แถว
- **5.5** เมื่อไรควรย้ายออก: ข้อมูลอยู่ที่ไหน · ดึงกลับได้ไหม · เกณฑ์ตัดสินใวย้ายไป self-host

### ส่วนที่ 6 — ผนวก
- **A.** Cheat sheet 1 หน้า (คำสั่งที่ใช้บ่อย + ปุ่มสำคัญ + ทางลัด)
- **B.** Integration ที่คนไทยใช้บ่อย (ต้อง verify ว่ามีจริง: Gmail, Google Calendar, Slack, Notion, LINE, GitHub)
- **C.** คำถามที่พบบ่อย (FAQ 15 ข้อ)
- **D.** อ่านต่อที่ไหน + **วันที่ข้อมูลถูกตรวจ** (stamp วันที่ทุกครั้งที่อัปเดต)
- **E.** Colophon: ผู้เขียน · แหล่งข้อมูล (rakazo.com/docs, /pricing) · ข้อจำกัดความรับผิด

## อุปกรณ์เฉพาะของเล่มนี้ (ต่างจากเล่มที่ 1)
1. **กล่องตัวอย่าง prompt** (แทนกล่องคำสั่ง Terminal) — เป็นแกนของเล่ม เพราะ "พูดกับบอท" คือทักษะที่ต้องฝึก
2. **ภาพหน้าจอจริง + คำอธิบาย "ตอนนี้คุณอยู่ตรงไหน"** — ผู้ใช้ทั่วไปหลงตำแหน่ง
3. **กล่อง "ราคา/เครดิต"** ในทุกจุดที่มีค่าใช้จ่าย ไม่ซ่อนไว้ท้ายเล่ม
4. **ตาราง "ถ้าคุณ… ให้ทำแบบนี้"** — แทนการสั่งตรง ๆ
5. **ระดับความยาก 3 ชั้น** ทุกบท: อ่านอย่างเดียว / ทำตาม / ทำเอง (ต่อยอดจาก approval ladder ของเล่มที่ 1)

## ความเสี่ยง & ข้อกำหนดที่ต้องเคลียร์ก่อนผลิต
1. **ต้องมี account Rakazo Cloud จริง** — ถ้าไม่มี ผมทำได้แค่โครง + ข้อความจากเอกสาร แต่จะยืนยันหน้าจอ/ปุ่ม/ราคาไม่ได้ (เล่มนี้จะมีข้อผิดพลาดในจุดหน้าจอ)
2. **UI เปลี่ยนได้ตลอด** → เขียนแบบทนการเปลี่ยน: อ้างตำแหน่งกว้าง + ภาพหน้าจอ + วันที่ · ห้ามเขียนระดับพิกเซล · มีกล่อง "UI เปลี่ยนไปไหม?" ในบทที่ไว
3. **ข้อมูลราคา/แผนเปลี่ยนได้** → ทุกตัวเลขต้องมีวันที่กำกับ (อ้าง rakazo.com/pricing ณ 18 พ.ย. 2026)
4. **ไม่คัดเนื้อหาจากเอกสารประกาศมาซ้ำเป็นเรื่องเล่น** — คู่มือต้องเป็นของผู้อ่านเอง เขียนใหม่ทั้งเล่ม
