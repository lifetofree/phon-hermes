## System Diagnostic 3-error + protocol form (HISTORICAL — explicit request only)

(HISTORICAL FORM — pre-#12 architecture kept for provenance; use ONLY when the user explicitly asks for named Errors + XX-0N protocol + Laws mapping; otherwise a system brief drafts in CURRENT FORM with principles unlabeled.) **Recurring brief format — "System Diagnostic (แก่นเชิงระบบ)" with 3 bullet errors + a "3 Laws mapping" (given ~5× now, incl. Reasons to Quit / Quick Wins / Hero Complex / Chunking Engine / Long List):** the user's 3 bullets map **1:1** to the 3 named Error sections and to the 3 protocol commands (one command per error, named **XX-0N** from the theme, e.g. QUIT-50 / SHIP-01 / HERO-01 / CHUNK-01 / LIST-01), and the "3 Laws mapping" text fills the ผูกกลับ Duck OS section verbatim-in-spirit (Law #1/#2/#3 one line each). Verify each error against a primary/academic source before building it (a "neuroscience angle" request = ground each error in a specific brain region/mechanism + a citable study). **Protocol-naming discipline:** before minting a NEW XX-0N name, count the corpus inventory (STYLE_CORPUS.md / index.json — already 40+ names); mint one ONLY when the system is proven (the user has run it, or a prior post demonstrates it). Otherwise ship a named time-budgeted experiment (e.g. "30-day Pattern Watch") WITHOUT a protocol name — naming faster than evidence forces readers to learn a glossary before they can use the insight (the OPB Complexity Test: an asset must REDUCE cognitive load, not add it). When the user asks for a **"medium form"** draft (recurring request since 2026-09-13): target ~500–650 words — between the web A-post range and the 2500–3000-word core long form — in the 2026-09 headingless "."-separated format, with the standard Type-A skeleton: hook → misdiagnosis move in the SOFTENED published form ("เราก็พยายามบอกตัวเองว่า…" — do NOT use the literal "วินิจฉัยโรคผิด (Misdiagnosis)" line; the published corpus keeps it 0/15) → source/quote with primary-source verification → named protocol **XX-0N** with exactly 3 commands + success criteria (the `--commands` ALWAYS survive the user's publish edit — never cut or soften them) → มุมของ Duck OS (3 Laws) → cross-refs to 2–3 earlier posts → #สรุปแบบวิศวกรเป็ด (hash form) → one-line sign-off ("System > X." + short Thai tagline; 🦆⚡ optional — the user strips it about half the time) → hashtag core + topic tags. **Write hooks/body in the published register — เรา/คุณ with sparse คับ — reserving พร for expert-credence lines and tool-review asides.** The user systematically swaps พร→เรา and trims ~10–15% before publishing (pub = 87–107% of draft length), so drafting in the published form minimizes their edit workload; the measured pattern lives in STYLE_CORPUS.md `## Updates` — draft guidance follows the freshest Updates entry when it conflicts with this skeleton.
   When the user asks for a **long form / core** draft ("long form", "core"): switch to the **heading-based** Type-A skeleton instead of the headingless one — `## 00: Ingestion Phase` → `## 01:`/`## 02:`/`## 03:` (the 3 errors) → `## 04: Protocol XX-0N` (3 commands under `### Step N:` subheads) → `## 05: ผูกกลับ Duck OS` (3 Laws) → cross-refs → **`## บทสรุปจากพร`** closer (NOT `#สรุปแบบวิศวกรเป็ด`). **No 🦆⚡ sign-off line in long form** — it ends on the บทสรุปจากพร paragraph + hashtag core; the 🦆⚡ one-liner is the medium form's. **Word-count calibration (Thai):** the nominal targets are rough — `wc -w` on Thai undercounts (no inter-word spaces). Real measured bands that passed review: medium ≈ 600–1100 `wc -w` (nominal 500–650); core/long ≈ 1000–2800 `wc -w` (nominal 2500–3000). Judge by the band and structural completeness, not the exact figure — a structurally-complete draft at the edge of the band is fine; don't pad to hit a nominal number.
