# Content Critique Cycle (Benz-DNA track)

## When to Use

Load this when a Benz-DNA comment (real, pasted from the owner) or a simulated Benz critique is being implemented on an adduckivity draft — intake, gate, publish-keys, pair closure, and the fold-learning step. Do NOT load for pure drafting (that is `content-pipeline`).

Overview: use when a real or simulated Benz-DNA critique arrives on an adduckivity draft — implementing it is a DIFFERENT job from writing the draft. This skill owns that job end-to-end: intake → verify → implement → gate → publish-keys → close. Writing/rewriting rules live in `content-pipeline`; that SKILL.md keeps only a pointer here plus its critic-side patterns (r2-cycle, r3-shape, §12 rule).

## Round type selector (read first — fold 359 two-round contract)

- **Critique + no publish version** → agent may rewrite (gate by paste, owner answers, spec → rewrite) — EXCEPT owner-authors track: owner announces it.
- **Critique + "publish version" pasted from the critic** → NO agent rewrite: archive → baselines → publish-keys only. The skill-learning step STILL runs.
- **Critique + owner gate answer + owner publish arriving in ONE message** (the fastest full round; recurring on the news-event lane) → the publish's own framing answers the gate — do not re-ask via clarify and do not rewrite. Round = archive both paste files byte-true → quote-verify the critique against the current draft → measure the publish in code (no HTML header) → grade against the critique's keys (the critic's recommended replacement lines are the keys, verbatim-or-function) → rebuild the same Notion page to Status `published` → fold the loop (content-pattern lessons to content-pipeline folds; this round-shape stays described HERE). Un-chosen gate axis = 0 in the publish; a minority-axis phrase surviving as a subordinate clause is a NOTE, not a FAIL.
- **Owner answers a gate in one message** ("เลือก a แล้ว rewrite เลย") → agent-rewrite round; grade the eventual publish against the LAST REAL critique's keys, never the agent's own vocabulary. Grade each key BY DEFINITION (what it permits/forbids in the publish), never by a proxy count — mention counts drift when the critic splits or merges sentences, and a key failed on a miscounted proxy is a wrong entry in a permanent ledger; recheck every apparent FAIL against the key's own wording before recording it.
- **Critique carries NEW SYSTEM FACTS — reposition round (pair #123 round, 2026-11-19, folds 439-442 in content-pipeline):** the paste is an ANALYSIS (change log + corrected mental model + repositioned thesis), not a line-edit list — run: extract → challenge (only misunderstanding-breaking questions) → reconstruct (current state / actual workflow / capability / limitation / future state, each sourced) → reposition the thesis → OWNER APPROVES the direction → rewrite LAST. Deliverable order: Original Thesis / Misunderstandings / New Information / Change Log / Revised Thesis / Recommended Structure / Rewrite (on approval) / Fact Audit. Machine-verify every new fact against the source system before it enters the ledger (roster counts carry an as-of date — they move within a day); garbled proper names (STT class) correct against the roster; never rewrite while a detected misunderstanding is unresolved; if the reposition retitles, the old title is DEAD vocabulary for the rewrite's checks. A wholesale proposed replacement skill ("OPB Article RE & Editorial Intelligence" shape) is NOT adopted over the existing two-skill split — extract its non-duplicative stages into folds instead (owner directive 2026-11-19).
- **Critique arrives as a RETROSPECTIVE ROUND SUMMARY — Benz DNA v2 shape (pair #125, 2026-11-21):** the paste is a multi-round document (r1 findings + owner's new data + owner's revision list + r2 re-audit + audience-feedback analysis + the critic's own generalized lessons section) about an already-POSTED article — no rewrite track. Run: archive the summary (PROVISIONAL class if owner-pasted inline; replace with byte-true pastes if they surface later) → grade the posted version against the critique's OWN lessons section → report residual defects to the owner (what the lessons demand that the posted text still violates — e.g. #125 shipped with 253−211≠41 unresolved, no Notion-doc link, the 7-rows cause-mix) → fold: post-pattern rules → content-pipeline folds (449-460), the critic's METHOD → the "v2 retrospective-round pattern" paragraph there. Signature of the v2 method worth reproducing in any future sim: the open-findings ledger (r2 re-audits r1's items and names which persist) — implement critique rounds the same way, never re-derive findings from scratch.
- **Critique lands on a draft the owner has ALREADY published, with a learn-only directive ("ไม่ต้องแก้ใน draft — เอา comment ไป reverse engineering/analyze/learning", left-digit round 2026-11-21):** archive critique + publish (PROVISIONAL-inline class ถ้า paste จากแชต) → quote-verify against the version the critic ACTUALLY read (หน้า Notion drift ทำให้ต่างจาก vault md — verify กับเวอร์ชัน Notion) → grade the publish against the critique's named fixes → report residuals → fold lessons (content-pattern → content-pipeline folds; round shape → round-type ที่นี่). NO rewrite, NO Notion rebuild/retitle/Status-flip — publish กับหน้า draft diverge กันโดยเจตนา owner ให้บันทึก ไม่ใช่ให้ซ่อม; grading against publish-keys เป็น optional เมื่อ directive ระบุ deliverable = learning
- **Critique arrives as a RULE-LEDGER — ก่อนแก้/หลังแก้/เพราะ/กฎ รายข้อ + "กฎรวม สำหรับ train AI" + ส่วน emotion — on a draft that is already published/fixed, learn-only directive (9router-fallback round 2026-11-23):** critic ถอดกฎมาให้เองครบ — รัน learning step แบบ VALIDATION ไม่ใช่ derivation: quote-verify บรรทัด "ก่อน" และระบุเวอร์ชันที่ critic อ่าน (อาจเป็น owner-updated draft ที่ไม่เคยเข้าระบบเรา — หน้า Notion อาจยังถือ v1 เก่า ให้ archive v1 snapshot ด้วย), ตรวจทุก fact ที่ critic ใช้ตัด/คง กับแหล่งจริงด้วยตัวเองแล้วจดผลใน archive header แม้ขัดกับคอมเมนต์ (publish ของ owner ยืนตามเดิม ไม่แตะ), dedupe กฎที่ถอดมากับ folds เดิมทีละข้อ (wire เป็น extends), เกรด publish กับกฎ BY DEFINITION ในโค้ด, แล้ว fold — กฎเนื้อหา → content-pipeline folds, รูปแบบรอบ → bullet นี้ บล็อก "กฎรวม" ใช้ต่อเป็น portable voice spec ได้ — คัดลอกลง fleet voice guide (`duck-os/Rakazo_Drafting_Voice_Guide.md`)
- **Critique lands on the NEWEST sibling of a product series, learn-only directive phrased "engineering/analysis/learning" (pair #OpenBot-copilotkit r1, 2026-11-27):** Benz รู้เรื่องซีรีส์อยู่แล้วเอง (จับชื่อผู้พัฒนาขัดข้ามชิ้นจาก memory ข้อ 1) และประกาศว่ายังไม่ได้ตรวจ fact กับเว็บทางการ + ส่งรายการ "ตรวจก่อนเผยแพร่" มาเป็น checklist → รัน: archive (PROVISIONAL-inline) → quote-verify กับหน้า Notion ปัจจุบัน (เวอร์ชันที่ critic อ่าน drift เท่าไร) → **Hermes รับโควตา fact-audit เอง = ครึ่ง engineering ของรอบ:** ตรวจทุกข้อในรายการ "ตรวจก่อนเผยแพร่" กับแหล่งทางการ (README/pricing/webinar) + ตรวจข้อที่ critic อ้างข้ามชิ้นกับหน้าจริงทั้งสอง → เขียนผลเป็นตาราง F1-Fn ใน archive พร้อม URL → "ต้องแก้ก่อน" + fact-deltas = publish-keys สำหรับเกรด publish ในอนาคต → NO rewrite, NO Notion touch; fact ที่ตรวจแล้วขัด draft (เช่น notarization พลิกแล้ว) รายงานเป็น decision list ไม่แก้เงียบ ๆ

- **Critic-verified round on a NEW GENRE first piece (gadget/hardware Thai review), learn-only "publish coming later" (pair #vivo-x500 r1, 2026-11-27):** Benz รอบนี้**ตรวจสเปกเองแล้ว** ("ผมค้นสเปกมาเทียบแล้วหนึ่งรอบ ส่วนใหญ่ตรง มีจุดสำคัญไม่ตรง") — ผลการตรวจของ critic มี timestamp: ข้อมูลเขา pre-launch ขณะ draft หมายวัน post-launch (อินเดียเปิด 26 พ.ย.) → fact-audit ต้องทำ 2 ทิศ: (1) **re-anchor ข้อแก้ของ critic กับแหล่งทางการ ณ ตอนประมวลผล** แล้วรายงานว่าข้อไหน "แก่ตามเวลา" ไปแล้ว (7800mAh ยืนยันแล้ว / เปิดตัวแล้ว + ราคาออกครบ / อุปกรณ์เสริมมีจริง) **โดยไม่ตีเป็นการแย้ง critic** — กระบวนการของเขา (ตรวจก่อน publish) ถูก ข้อมูลเขาแก่ตามเวลา; (2) **เกรดตัวเลขของ draft เองกับหน้าทางการ** (7800 ✓ / จอ Pro Max หาย / ราคา×0) — เจอ spec-sheet 3rd party ขัดทางการ ให้จดลงด้วย (8000 vs 7800) → publish-keys รวมทั้งข้อที่ critic ยืนยันแล้วยังยืน (ขนาดจอ/ตรรกะ) และข้อที่ fact ยกฟ้อง (7800/เปิดตัว/อุปกรณ์ = คงไว้+อัปเกรดด้วยเลขทางการ) → NO rewrite ตาม directive ("เดี๋ยวเอา publish version มาให้")

- **Owner sovereignty over gates:** when the owner's gate answer contradicts the critic's recommendation, the spec follows the OWNER's answer verbatim (pair #103 r3: owner picked ข้อแรก, Benz แนะข้อสอง → Benz served the owner's answer and supplied closer lines).

- **Critique lands on a COMPARISON/product-review DRAFT pre-publish, learn-only directive (pair #AI3way r1, 2026-11-25):** the draft itself claims fairness ("ไม่อวย") while its table axes favor the author's product and rival losses are skipped. Run: archive → validate the critic's factual checks (date, cross-post consistency) → fold comparison-genre rules (504-511) + the critic's method (below) → NO rewrite (owner directive) → report residual decision list to the owner (title choice, patch approvals, stale archives).

- **Critique lands on the latest draft that a PARALLEL session rewrote EARLIER THE SAME DAY, learn-only directive, "published content coming later" (pair #OpenBot-local r1, 2026-11-26):** archive (PROVISIONAL-inline) → establish WHICH version the critic read from his own praise/quotes (the praised สรุปแบบวิศวกรเป็ด format exists only in the post-rewrite version) → quote-verify against the CURRENT Notion page, but read the vault snapshots for version lineage first → verify the critique's claims about OTHER published pieces directly against those pieces' Notion pages (the "ง่ายที่สุด/ฟรี" claims confirmed on 423df8d8… before folding the cross-post lesson) → the critique's "ต้องแก้ก่อน" list = the publish-keys for grading the owner's future publish (graded when it arrives) → NO rewrite, NO Notion touch; residuals discovered on the way (a page accidentally duplicated by the same-day rewrite echo — identical halves verified in code; patching the published sibling) go to the owner as a decision list, not silent fixes.

### Benz r1-real folds — comparison-article draft (pair #AI3way, 2026-11-25; genre: product comparison)

The critique on the Rakazo-vs-OpenBots comparison draft added five method moves specific to comparison/review pieces:

1. **Declared verification budget up front:** "ผมยังไม่ได้ตรวจข้อมูลของ OpenBot ทั้งสองตัวกับเว็บทางการ ตัวเลขและฟีเจอร์ในตารางต้องเช็กอีกรอบก่อนเผยแพร่" — the critic states WHAT he has NOT verified and orders it as a mandatory pre-publish gate. Unverified-by-critic ≠ wrong; it is work still owed.
2. **Fairness-claim audit against the draft's own words:** the draft says "แบบไม่อวย" → the critic TESTS the claim: table axes favor the author's product, rival-loss rows are skipped, double standards found ("ปิดคอม ทีมหยุด" applies to the author's own server). Rule: every self-description ("fair", "honest", "ไม่อวย") is a claim to be audited, not a discount.
3. **Absolute-claim risk grading:** "ไม่มีทางสั่งงานจากมือถือ" — one counterexample destroys the whole table's credibility. Rule: absolutist phrasing in comparison pieces must carry exhaustive evidence or be softened.
4. **Cons-depth symmetry + audience-scoped criticism:** the author's own cons run 3 words while rivals get paragraphs; and criticizing Business pricing aimed at personal-use readers = criticizing something that audience never encounters. Rule: cons depth ≥ pros depth; scope every criticism to what the target reader actually faces.
5. **Cross-post consistency check:** "เผยแพร่เร็วนี้" contradicts the author's earlier survey post that said no sales decision had been made. Rule: claims about product status must hold consistently across ALL posts about the same product.
6. **Fix-order directive by credibility impact:** วันที่ → privacy overclaim → ownership clarity → disclosure moved to line 3 → add rival-winning table rows → verify rivals' official sites. Rule: when listing fixes, ORDER them by how much each affects trust.
7. **Ownership-identity question as gate:** "Rakazo เป็นของใคร สร้างเอง/ดัดแปลง/ใช้ของคนอื่น?" — in comparison pieces the author's relationship to each compared product (builder vs installer vs user) must be declared; it changes how every advantage is read.

### Benz r1-real folds — OpenBot local-first draft (pair #OpenBot-local, 2026-11-26; genre: tool-intro, docs-only first-look)

Benz critiqued the rewritten OpenBot deep-dive draft (learn-only round; publish comes later). Method additions on top of the AI3way/NR grammar:

1. **(OB1) Double disclaimer opening:** read-coverage declaration ("ผมยังไม่ได้ตรวจข้อมูลกับเว็บ openbot.run") PLUS job-scoping ("ข้อวิจารณ์เป็นเรื่องการเขียนและความสอดคล้อง…ไม่ใช่การยืนยันความถูกต้องของข้อเท็จจริง") — the critic names WHICH job he is doing so the writer knows what the round does NOT cover (extends NR1 read-coverage transparency).
2. **(OB2) Heaviest item first = cross-ARTICLE contradiction, fix ordered on the PUBLISHED piece:** the new piece's honesty exposed the published sibling's oversell ("ง่ายที่สุด…ไม่แตะเซิร์ฟเวอร์" / "ฟรี" — Hermes verified both still live on the published page) — Benz orders the cut + the license addition on the PUBLISHED article, justified by BRAND stakes ("ผู้อ่านที่ทำธุรกิจต้องรู้ข้อนี้ก่อนตัดสินใจ") — brand context sets fix priority.
3. **(OB3) Evidence-symmetry propagation:** the newer piece's honesty label must be added to the older sibling too ("ใส่ประโยค 'จากเอกสาร ยังไม่ได้ลองเอง' ในบทความเปรียบเทียบด้วย") — one evidence class per product across ALL pieces.
4. **(OB4) Section-title audit against the title's evidence class:** "สิ่งที่ชอบ" implies use-experience while the title says never-installed — supplies the replacement header AND the reason ("เป็นข้ออ้างของเอกสาร ไม่ใช่สิ่งที่คุณพิสูจน์เอง").
5. **(OB5) Caveat-proximity rule:** the warning already exists in the piece (ชั้น 2) — the fix is MOVING it adjacent to the "100%" sentence, not adding content; the critic tracks what the piece already says and orders relocation.
6. **(OB6) Unverifiable-terms flag with a FALLBACK SENTENCE supplied:** BYOS/provider-ToS — "ผมยังไม่ได้ตรวจ ถ้าไม่ชัวร์ ใส่ว่า 'ควรอ่านเงื่อนไขของผู้ให้บริการก่อน'" — when neither critic nor writer can cheaply verify, the critique ships the hedge text itself (contrast W1, which orders a 10-minute check when the tool CAN answer).
7. **(OB7) Disclosure-completeness audit:** "เราไม่มีส่วนเกี่ยวข้องกับทีมผู้พัฒนา" is half a disclosure while the author USES the competing compared product (Rakazo) — one line + link to the comparison article.
8. **(OB8) Voice-census across the series:** เรา→พร mixing mid-piece; the instruction is to match OTHER articles ("ให้ตรงกับบทความอื่น") — voice = cross-article invariant, same family as W5 closer-shape.
9. **(OB9) Doc-provenance requirement:** "อ่านจากเอกสารทางการและ release notes" without URL/version = readers cannot re-check AND staleness becomes invisible ("ข้อมูลจะล้าสมัยโดยไม่มีใครรู้") — extends W6 producer-claim-link to doc-version staleness.
10. **(OB10) Channel-gate QUESTION instead of a format ruling:** "ผมไม่แน่ใจว่าชิ้นนี้ไปลงที่ไหน" — conditional per-channel advice (spacer-dot lines acceptable on Facebook, garbage on WordPress; markdown `##`/`>`/`-` render as literal symbols on Facebook), ruling withheld until the writer states the destination.
11. **(OB11) Logic-flag + replacement-line move:** "ตรรกะ 'เอกสารยาว ไปต่ออย่าเชื่อ' อาจไม่ถูกเสมอ" + the corrected sentence written out — inference errors ship as replacement lines, not just verdicts.
12. **(OB12) Close = fix-order by trust impact + keep-list + series-identity praise:** "ลำดับแก้ที่แนะนำ" ordered; four keeps named ("จุดที่ดีและควรเก็บ") with the [สาระ][เงื่อนไข][มุมสังเกต] closer elevated to series identity ("สร้างเอกลักษณ์ซีรีส์ได้ดี") — the keeps are protected anchors for the rewrite (extends AI3way move 6 + NR8).

### Benz r1-real folds — Vivo X500 gadget draft (pair #vivo-x500, 2026-11-27; genre: Thai hardware review, learn-only "publish coming later", critic pre-verified specs)

Critic arrived SELF-VERIFIED ("ผมค้นสเปกมาเทียบแล้วหนึ่งรอบ") with a weighted verdict ("ส่วนใหญ่ตรง มีจุดสำคัญไม่ตรง") — method additions on top of OC1-OC9:

1. **(OD1) Weighted audit verdict, not blanket trust:** "ส่วนใหญ่ตรง แต่มีจุดสำคัญที่ไม่ตรง" — he grades the piece AS A WHOLE first (มุมดี อ่านลื่น เข้าซีรีส์), then surgically names the load-bearing wrongs (จอ framing, 7800) and orders them by argument damage ("สองข้อนี้ทำให้ข้อโต้แย้งหลักผิด") — praise and verdict coexist; the ordering is by DAMAGE TO THE THESIS, not by fact-count.
2. **(OD2) Omission-manufactures-trend catch:** the "รุ่นท็อปเล็กลง" framing fell because Pro Max's 6.85″ was LEFT OUT of a 3-member set — he lists all three sizes and reconstructs the true story ("มีรุ่น Pro กะทัดรัดเพิ่ม…สื่อเรียกว่าการกลับสู่เรือธงกะทัดรัด") — the critic doesn't just kill the claim, he supplies the CORRECT trend narrative + its press-consensus name.
