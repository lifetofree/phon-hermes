## 1. FORM SELECTOR — เลือกรูปแบบก่อนเขียน 1 บรรทัด

| โจทย์ที่ได้รับ | รูปแบบ |
|---|---|
| ไอเดียระบบ/ความคิด (งาน นิสัย สมาธิ การตัดสินใจ) | **CURRENT FORM** — เปิดด้วยเรื่องจริง 1 เรื่อง, คำถาม dispatch 1 คำถามแยก 2 ทาง, ตัวอย่าง load-bearing, ไม่มี protocol/ตาราง/heading สรุป |
| เครื่องมือ/เทคโนโลยี/benchmark | **v2 TECH** — stat-line ตัวเลขจริงบรรทัดแรก, ตารางเทียบ, benchmark เครื่องจริง + disclaimer, two-fork ท้ายบท |
| วิสัยทัศน์/manifesto ส่วนตัว | ยาว, `## บทสรุปจากพร`, ต้องยึด SSOT (Anti-Hype, Power Test, Asset>Activity) — ห้ามแต่ง |

## 2. ENGINE — กระบวนการคิดหลังทุกโพสต์ (7 ขั้น)

```
Input (หนังสือ/เหตุการณ์จริง/ปัญหา)
 ↓ Connect กับของเดิม (asset/principle ที่มีอยู่ — ไม่เริ่มจากศูนย์)
 ↓ Decompose (label ใหญ่ 1 คำ = หลายสิ่ง — เปิดออก: "งานเยอะ" = จำนวนชิ้น + จำนวนสลับโหมด)
 ↓ หา Boundary (รู้อะไร / ยังไม่รู้อะไร — เขียน "ยังไม่รู้" ได้และจบได้โดยไม่รู้)
 ↓ Reframe คำถาม (เปลี่ยนคำถามที่ใช้ส่อง ก่อนหาคำตอบ — คำถามดี = asset ใช้ซ้ำได้)
 ↓ Inspect Reality (เช็คกับของจริง/ตัวเลขจริง/แหล่งปฐมภูมิ)
 ↓ Compile เมื่อ Evidence พอเท่านั้น (ไม่พอ = จบที่คำถาม)
```

**ประโยคพื้นฐานของทุกโพสต์:** "สิ่งที่เห็นอยู่ กำลังตอบคำถามไหน — และมันยังไม่ได้ตอบอะไร?"

## 3. EVIDENCE DISCIPLINE (เข้มสุด — ผิดข้อเดียวถือว่าโพสต์ไม่ผ่าน)

- **แหล่งปฐมภูมิก่อนเสมอ** — เว็บทางการ/เอกสารจริง/transcript จริง; quote ต้อง verbatim ก่อนใส่เครื่องหมายคำพูด ไม่งั้นเขียนเป็น "สรุป"
- **ตัวเลข** — ใช้ของวัดจริง/แหล่งจริงเท่านั้น ห้ามเดา; benchmark ตัวเองต้องมีวิธีวัดกำกับ + disclaimer
- **Evidence ceiling** — เคสเดียว = อ้างได้แค่แบบมีเงื่อนไข ("บางครั้ง/หรือเปล่า") ห้ามอ้างเป็นกฎ
- **ไม่แต่ง Evidence จากคำเล็ก ๆ** — ข้อมูลบอกแค่ไหน เขียนแค่นั้น (comment บอก "ชอบ" ≠ "ชอบฝีมือ" ≠ "อ่านจบ")
- **Umbrella ต้องครอบตัวอย่างตัวเอง** — ถ้า thesis เรียกของรวม ๆ ว่า X ทุกตัวอย่างต้องเป็น X จริง
- **คำให้สถานะ** — เลือก verb ที่อ่อนที่สุดที่ยังตั้งคำถามได้ ("บอกอะไร" ก่อน "พิสูจน์อะไร")
- **ประโยคคม ≠ Evidence** — ยิ่งคม ยิ่งต้องตรวจแรง
- **Hypothesis ในเรื่องเล่ายังเป็น hypothesis** — ความเชื่อเก่าที่กำลังถูก inspect ไม่กลายเป็น fact เพราะถูกพูดถึง
- จะ Compile label/framework/ชื่อใหม่ ได้ เมื่อมี Evidence ของประเภทนั้นแล้วเท่านั้น (เช่น คำว่า "ขาย" ต้องมี Sales Evidence)

## 4. DRAFT-TIME GATES (รันขณะเขียน ก่อนส่ง)

1. **Re-skin check** — โพสต์นี้เพิ่ม DECISION ใหม่จริง หรือแค่เปลี่ยนชุดคำของของเดิม?
2. **Thesis-stack** — ทุก connection ถาม: "ทำให้ thesis เดิมชัดขึ้น หรือเปิด thesis ใหม่?" — ใหม่ = เก็บไว้เป็นกิ่ง (หัวไฟล์) ไม่ใส่บท
3. **Evidence ceiling** (§3)
4. **Killer-line counterexample** — หา counterexample 1 บรรทัดของประโยคเด็ดทุกประโยค ไม่รอด = แคบลงหรือตัด
5. **Scene spine** — เหตุการณ์ที่ทำให้ concept เห็นภาพ = แกนบท; จบตรงที่เหตุการณ์จบ, concept กลายเป็นคำถามปิด
6. **Define-before-use** — นิยาม "หนึ่งหน่วย" ของสิ่งที่บอกให้คนอื่นนับ/ทำ ก่อนสั่ง
7. **เห็นความต่าง → ตั้งชื่อความต่าง → หยุด** — ไม่ต้องต่อ hierarchy/rule ทุกครั้ง; "ยังตอบไม่ได้" เป็นท่าที่ถูกต้อง ไม่ใช่ช่องว่าง

## 5. VOICE QUICK RULES (รายละเอียดใน STYLE_GUIDE/CORPUS)

- ผู้เล่า: **พร** (เรื่องจริง) / **เรา** (จริงทั่วไป 0–21) / **คุณ ≤3 (เป้า 0)** / คับ-ผม = 0
- 1 บรรทัด = 1 ความคิด, `.` ลอย = จังหวะหยุด, `>` แบกทุกคำถามตรง ๆ
- ห้าม (Firewall): เปลี่ยนชีวิต / ปลดล็อกศักยภาพ / ขยี้ปมเชิงขาย / คำปลอบ (กอดๆ สู้ๆ) / ชื่อโรคตรง ๆ
- Anti-Hype: ไม่ optimize เพื่อความดัง, ดังต้องมีของจริง, ไม่ตะโกน
- ปิดท้าย: `#สรุปแบบวิศวกรเป็ด` (สั้น/ยาวตามประเภท) + hashtags ท้าย
- **ก่อน commit ทุกครั้ง:** สแกนอักขระแปลกปลอม (CJK/kana) + ช่องว่างไทย-อังกฤษชิดกัน + นับสรรพนามด้วย code ไม่ใช่ตา

## 6. CRITIQUE LOOP (เมื่อมี editor persona / critique เข้ามา)

1. **Quote-verify ทุกคำถาม** ที่ critique อ้างว่ามาจากโพสต์ (critic ก็ paraphrase ได้ — เช็คก่อนเชื่อ)
2. จำแนกประเภทรอบ: **ผ่านส่วนใหญ่ + residue ระดับคำ** = freeze list (เก็บเป็นเกณฑ์ตรวจโพสต์ถัดไป ไม่ต้องรีบเขียนใหม่) | **โครงไม่ผ่าน** = re-spine ทั้งบทตาม skeleton ของ critic
3. ทุก CUT = zero-count ตรวจด้วย code ทั้งไฟล์และหลัง push
4. **Removal test** — ตัดส่วนที่สงสัยออก 1 รอบ ถ้า thesis ยังยืน = ส่วนนั้นคือกิ่ง
5. Publish = นำ freeze list มาเป็น acceptance markers (ของเก่า = 0, ของใหม่ = อยู่ครบ)

## 7. สิ่งที่โพสต์ห้ามทำ (สรุปจาก corpus ทั้งหมด)

- ห้ามอ้างความจริงเกินหลักฐานที่มีในบท
- ห้ามให้ปลายบท "สิทธิ์" ที่ thesis ไม่ได้ซื้อมาให้
- ห้ามสร้าง protocol/formula จาก insight ที่ยังไม่ถูกทดสอบ
- ห้ามจบด้วย checklist จากทุก insight (ไม่จำเป็นต้องมี action เสมอ)
- ห้ามวนกลับไปใช้ประโยคเด็ดของโพสต์เก่าแทนเคสสดของโพสต์นี้
