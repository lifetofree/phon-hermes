## 00: ของที่เกิดตอนพรไม่อยู่หน้าจอ

พรไม่ได้เปิดแอปนี้ทุกวัน

แต่ทุกเช้า 8 โมง มันส่งรายงานจำนวนผู้ใช้จากฐานข้อมูลจริง (Cloudflare D1 ของโปรเจกต์ task-logger) เข้า Telegram ให้พรเอง — สถานะรอบล่าสุด: ok

1 เดือนกว่าที่ใช้มา งานเขียน 43 ไฟล์ผ่านมือมันในเครื่องเดียว และในเครื่องนั้นมีทักษะที่มันเรียกใช้เองได้ 95 ตัว

บทความนี้เขียนจากของจริงในเครื่อง ไม่ใช่จากหน้า marketing

ถ้าคุณเคยใช้ AI แล้วรู้สึกว่ามัน "ฉลาด แต่รอคำสั่งอยู่กับที่" — ช่องว่างตรงนั้นแหละคือทั้งเรื่องนี้

คำถามแท้จริงของบทความนี้ไม่ใช่ "AI ตัวไหนฉลาดที่สุด" แต่คือ "งานไหนของคุณ ที่ AI น่าจะทำเองโดยไม่ต้องมีคุณนั่งกดปุ่ม"

(ต่อซีรีส์ AutoClaw: Part 1 แนะนำเครื่องมือ — Part 2 จับคู่ ZCode — Part 3 ถามว่า runtime ของ agent ควรอยู่ที่ไหน — Part นี้ถอยหลังหนึ่งคำถาม มาตอบว่าคุณควรมี runtime ของตัวเองเลยไหม และเมื่อไหร่)

## 01: ยอมก่อน — ใครไม่ควรอ่านต่อ

ถ้างานคุณคือเปิดแชตถาม AI วันละสองรอบ — อย่าเปลี่ยน

อ่านจบแล้วกลับไปทำงานต่อได้เลย ประหยัดทั้งเวลา setup ทั้งค่าเครื่องมือ — นี่ไม่ใช่น้ำเสียงเกรงใจ มันคือคำตอบจริงของโพสต์นี้

แต่ถ้าเจอสัญญาณข้างล่างนี้ตั้งแต่ 2 ข้อขึ้นไป — อ่านต่อ

## 02: 5 สัญญาณว่าคุณต้องการ agent runtime ไม่ใช่ chatbot อีกตัว

— คุณพิมพ์คำสั่งชุดเดิมซ้ำ ทุกวันหรือทุกสัปดาห์ (สรุปนู่น เช็กนี่ รายงานโน่น) — ถ้าคำสั่งซ้ำได้ แปลว่ามันมีโครง ถ้ามีโครง แปลว่าตั้งเวลาได้

— workflow ของคุณข้ามอย่างน้อย 2 แอป (โน้ตอยู่ที่นึง ปฏิทินอยู่ที่นึง แจ้งเตือนอยู่อีกที่) — งานที่ไหลข้ามแอปคืองานที่มนุษย์กลายเป็น "ตัวกลางขนข้อมูล" โดยไม่จำเป็น

— มีงานที่ "ควรเกิดตอนคุณไม่อยู่" — เช้าวันจันทร์ตื่นมาแล้วรายงานน่าจะรออยู่แล้ว ไม่ใช่รอคุณกดเก็บข้อมูลเอง

— คุณเริ่มเก็บ prompt ดี ๆ ไว้ในไฟล์ เพื่อกลับมา copy วางใหม่ทุกครั้ง — prompt ที่ถูกเก็บไว้ในไฟล์ คือ job description ที่รอถูกจ้างเป็นงานประจำ

— คุณอยากให้ AI เห็น "ของจริง" — ไฟล์ในเครื่อง เบราว์เซอร์ แชท — ไม่ใช่แค่ข้อความที่คุณแปะให้

เช็กตัวเองแล้วโดนกี่ข้อ?

ถ้าโดนยก่อนข้อ 3 — ยังไม่ต้องรีบ แชตยังพอ

ถ้าโดนตั้งแต่ 3 ขึ้นไป — ปัญหาของคุณไม่ใช่ "AI ไม่ฉลาดพอ" แต่คือ "AI ของคุณยังไม่มีตัวตนตอนคุณไม่อยู่"

## 03: Chatbot กับ agent runtime ต่างกันอย่างไร — คิดด้วยไฟบ้าน

Chatbot ทั่วไปเหมือน generator พกพา

มีไฟทุกครั้งที่คุณจ้ำจี้จ้ำไฟ แต่พอวางมือ มันเงียบ — ฉลาดแค่ไหนก็ไม่มีลูกน้ำที่ไหลเองตอนห้าโมงเช้า

AutoClaw เป็นอีกอย่าง — มันคือไฟบ้านที่ต่อเข้ากับวงจรจริงของเครื่องคุณ

สวิตช์แต่ละดวงต่อกับของจริง: ไฟล์ในเครื่อง เบราว์เซอร์ ปฏิทิน IM ที่คุณคุยจริง (Telegram, Slack, WhatsApp, Lark)

และจุดที่ต่างจาก generator ที่สุด — ตั้งเวลาได้ว่าไฟดวงไหนจะติดเองกี่โมง

ตารางเทียบสั้น:

| | Chatbot | Agent runtime (AutoClaw) |
|---|---|---|
| ทำงานเมื่อไหร่ | เฉพาะตอนคุณพิมพ์ | ตามตาราง (cron) + ตามคำสั่ง |
| เห็นอะไร | ข้อความที่คุณแปะให้ | ไฟล์ เครื่อง ปฏิทิน IM ของจริง |
| จดจำ | หมด context ก็จบ | ไฟล์ memory อยู่รอดข้ามวัน |
| เพิ่มทักษะ | รอ vendor อัปเดต | ติดตั้ง skill เอง (เครื่องที่เล่า 95 ตัว) |
| วัดกันที่ | คำตอบดีไหม | งานเกิดไหม ตอนคุณไม่ได้ดูอยู่ |

อ่านตารางซ้ำอีกรอบ — ทุกแถวไม่ได้เทียบความฉลาด มันเทียบ "การมีอยู่"

## 04: หลักฐานจากเครื่องจริง หลัง 1 เดือนกว่า

ก่อนนับตัวเลข ระบุเวทีให้ชัด: ทั้งหมดนี้อยู่บนเครื่องเครื่องหนึ่งที่พรแยกตั้งไว้ให้ AutoClaw ทำงานอัตโนมัติ — ไม่ใช่เครื่องหลักที่รัน local LLM 24/7 (เครื่องนั้นเล่าไปแล้วใน Part 3)

— งานอัตโนมัติ 1 ชิ้นที่ตั้งครั้งเดียว: ทุก 8 โมงเช้า ดึงจำนวนผู้ใช้จาก Cloudflare D1 ของโปรเจกต์ task-logger แล้วส่งเข้า Telegram — สถานะรอบล่าสุด ok — งานชิ้นนี้ไม่เคยต้องรอให้พรเปิดแอป

— โฟลเดอร์งานเขียนในเครื่องนั้นมี 43 ไฟล์ (54MB) — draft, rewrite, fact-check ล้วนผ่าน workflow ในเครื่องนี้

— skills ที่ติดตั้งไว้ 95 ตัว — หน้า official พูดแค่ "50+ built-in skills" ที่เหลือคือที่เพิ่มเข้าไปเอง — ตัวเลขจากเครื่องจริง เกินหน้า marketing

— ตัวอย่างเล็ก ๆ ที่พรชอบที่สุด: วันหนึ่ง debug เรื่อง Discord plugin ไม่ยอมโหลด มันจดสาเหตุกับข้อห้ามไว้ในไฟล์ memory เอง — อีกสองสัปดาห์ต่อมาเจอปัญหาเดิม มันไม่ต้องเจอซ้ำ — นี่คือแถว "จดจำ" ในตารางที่เป็นของจริง

ตอนเช้าพรเพิ่งตื่น มันทำงานไปแล้ว — เหมือนมีลูกน้องที่ตื่นก่อนเรา แต่ไม่ขอค่าโอเวอร์ไทม์

ส่วนค่าจ้าง ณ ต.ค. 2026: คนสมัครใหม่ได้ 200M tokens (มูลค่าประมาณ $24) + เครดิตฟรีรายวัน และถ้ามี GLM Coding Plan กดรับโบนัสรายเดือนได้อีก (Lite 5,000 / Pro 10,000 / Max 26,000 credits) — runtime ทั้งตัวเริ่มได้โดยไม่ต้องจ่ายก่อน

Disclaimer ตามเคย: ตัวเลขทั้งหมดวัดจากเครื่องของพร วันที่ 6 ตุลาคม 2026

อย่าเอาไปเทียบตรงกับ use case อื่นโดยไม่ควบคุมเงื่นไข — งานของพรเป็นงานเอกสาร-ข้อมูล-รายงาน ซึ่งเป็นสนามที่ runtime แบบนี้เก่งที่สุด

## 05: ส่วนที่ไม่น่าเชียร์ — อ่านก่อนตัดสินใจ

— 1 เดือนแรกเสียเวลา setup จริง — ไม่ใช่ one-click แล้วชีวิตเปลี่ยน — งานอัตโนมัติที่ "เกิดตอนหลับ" มีต้นทุนที่ "ตื่นมานั่งตั้ง" ก่อนหน้านั้น

— งานอัตโนมัติที่ตั้งผิด มันทำผิดทุกวันเหมือนกัน — พรเจอ job timeout มาแล้ว ต้องกลับมาแก้ — automation คูณความผิดพลาดเหมือนคูณความถูกต้อง ตัวเลขหน้าเครื่อหมายต้องมาจากคุณ

— มันเห็นเครื่องคุณจริง — เรื่อง permission กับไฟล์อะไรให้เห็น คือความรับผิดชอบของเจ้าของเครื่อง ไม่ใช่ของแอป — และอย่าลืมจาก Part 3: ตัวแอปรัน local แต่สมอง default วิ่งผ่าน API ของ Z.ai — งานที่ sensitive คุณต้องเลือกเองว่าจะให้มันไปถึงไหน

## 06: สองทางปิดท้าย

ทางแรก — ถ้าคุณแค่ "ใช้" AI:

ถาม ตอบ สรุป เขียนหัวข้อ — แชตตัวเดิมพอ

อย่าเสียเวลา setup เพราะ FOMO

เวลาที่เหมาะจะย้าย คือตอนที่งานเริ่มมี "ตารางเวลา" ไม่ใช่ตอนมีข่าวใหม่

ทางที่สอง — ถ้าคุณเริ่มต้องการให้มัน "ทำงานเอง":

เริ่มจากงานเดียวที่คุณทำซ้ำทุกวันจริง ๆ — ไม่ใช่งานที่ "น่าจะดีถ้าทำได้"

ตั้งเป็นงานตามเวลา (cron) 1 ตัว ปล่อยให้มันพิสูจน์ตัวเอง 2 สัปดาห์ — ดูแค่ว่ารายงานมาถึงไหม ตรงเวลาไหม ตัวเลขถูกไหม

ค่อยขยายเมื่อมันพิสูจน์แล้วว่าเชื่อถือได้ — ไม่ใช่ตั้ง 10 อันพร้อมกันแล้วเช็กไม่ไหว — agent 10 ตัวที่ไม่มีใครเฝ้า ไม่ใช่ระบบอัตโนมัติ มันค่าประสบอุบัติเหตุล่วงหน้า

## สรุปแบบวิศวกรเป็ด

ความเข้าใจผิดที่พบบ่อยที่สุดคือคิดว่าการย้ายจาก chatbot ไป agent runtime คือ "อัปเกรดความฉลาด" — ไม่ใช่ — ความฉลาดของโมเดลตัวเดิมก็ตัวนั้น สิ่งที่เปลี่ยนคือสัญญาจ้าง:

— **ถาม AI** = จ่ายต่อคำตอบ — คุณอยู่ใน loop ทุก step คุณคือปุ่ม power ของทุกงาน

— **จ้าง AI** = จ่ายต่อกะ — งานเกิดตอนคุณไม่อยู่ และมี memory สะสมประสบการณ์ข้ามสัปดาห์

คำถามแท้จริงของโพสต์นี้กลับมาอีกที: **งานไหนของคุณ ที่ AI น่าจะทำเองโดยไม่ต้องมีคุณนั่งกดปุ่ม?**

ช่องว่างที่โพสต์นี้ตั้งชื่อ: **ความฉลาดแบบ standby** — ฉลาด แต่รอคำสั่งอยู่กับที่ — ความฉลาดที่ไม่ถูกจัดตารางเวลา คือความฉลาดที่ไม่เคยถูกจ้าง

พรเคยทำอะไร: เปิดแชตถาม AI วันละหลายรอบ — คำตอบดี แต่ทุกงานเริ่มที่ปุ่มของพรเอง

ตอนนี้พรทำอะไรอยู่: งานที่ซ้ำทุกวันถูกย้ายไปอยู่บนตารางเวลา 1 ตัว — พรถือแค่คำถามว่าสัปดาห์นี้จะขยายกะไหน

ถาม AI ได้คำตอบ — จ้าง AI ได้งาน

และเวลาที่เหมาะจะเปลี่ยนสัญญา คือตอนที่งานเริ่มมีตารางเวลา — ไม่ใช่ตอนมีข่าวใหม่
