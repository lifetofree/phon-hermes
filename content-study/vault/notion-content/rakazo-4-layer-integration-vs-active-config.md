# ต่อแอปกับ Rakazo — ระบบรองรับ 4 ชั้น แต่บนเครื่องเราตั้งค่าไว้ 2 Integration

**Excerpt:** ต่อแอปกับ Rakazo ระบบรองรับ 4 ชั้น แต่บนเครื่องเราตั้งค่าไว้ 2 Integration ตรวจสถานะจากฐานข้อมูลจริง แยกสิ่งที่ระบบทำได้ออกจากสิ่งที่เราเปิดใช้แล้ว ต่อเฉพาะสิ่งที่งานต้องใช้ ไม่ใช่ต่อทุกอย่างเพราะระบบเปิดช่องไว้

ตรวจสถานะจากฐานข้อมูลและไฟล์ตั้งค่าบนเครื่องจริง ณ วันที่ 19 พฤศจิกายน — แยกสิ่งที่ระบบทำได้ ออกจากสิ่งที่เราเปิดใช้แล้ว
.
สี่ชั้นของการเชื่อมต่อ
เอกสารของทีมผู้พัฒนาแบ่งการเชื่อมต่อกับระบบภายนอกออกเป็น 4 ชั้น ได้แก่ โมเดล แอปสำเร็จรูป เครื่องมือที่เชื่อมต่อเอง และช่องทางแชต
ชั้นแรก — โมเดล
Rakazo รองรับการเชื่อมต่อโมเดลได้ 3 วิธี
ชั้นที่สอง — แอปสำเร็จรูป
มีแอปที่ทีมผู้พัฒนาระบุไว้ เช่น Gmail, Slack, GitHub, Notion และ Linear รวมถึงรายการอื่น ๆ อีกจำนวนมาก
แต่สำหรับการติดตั้งแบบ Self-hosted การมีรายการแอปอยู่ในระบบไม่ได้หมายความว่าจะใช้งานได้ทันที ผู้ดูแลต้องใส่ Key ของผู้ให้บริการ Catalog ก่อน รายการแอปจึงจะปรากฏให้เลือกใช้งาน
ชั้นที่สาม — เครื่องมือที่เชื่อมต่อเอง
รองรับเครื่องมือ 5 รูปแบบ ได้แก่
เอกสารระบุว่า Credential ของเครื่องมือเหล่านี้ถูกเข้ารหัส และไม่ได้ส่งให้โมเดลโดยตรง
ชั้นที่สี่ — ช่องทางแชต
รองรับ Slack, Microsoft Teams, iMessage/SMS, WhatsApp, Telegram และ Feishu/Lark
แต่ละช่องทางต้องใส่ Credential ให้ครบก่อนจึงจะเปิดใช้งานได้
ทั้งหมดนี้คือความสามารถที่เอกสารระบุว่าระบบรองรับ แต่ไม่ได้หมายความว่าทุกชั้นถูกเปิดใช้งานอยู่บนเครื่องของเราแล้ว
.
## บนเครื่องของเรา มี 2 Integration ที่ตั้งค่าไว้
จากการตรวจสอบฐานข้อมูลและไฟล์ตั้งค่า พบว่ามี Integration อยู่ 2 สายที่ตั้งค่าไว้ ได้แก่ Model Endpoint และ Notion MCP
สายแรก — Model Endpoint บนเครื่อง
บอตเรียกโมเดลผ่าน Endpoint ภายในเครื่องเดียวกัน โดยใช้รูปแบบ OpenAI-compatible
งานที่เรียกผ่าน Endpoint นี้จึงไม่จำเป็นต้องส่งไปประมวลผลกับผู้ให้บริการ API ภายนอก
ในระบบมีรายการโมเดลที่บันทึกไว้ 4 รายการ
เอกสารยังระบุว่าระบบสามารถกำหนดโมเดลสำรองเป็นลำดับได้ เมื่อโมเดลหลักใช้งานไม่ได้หรือถึงขีดจำกัด ระบบจะเลื่อนไปใช้โมเดลตัวถัดไปตามลำดับที่กำหนดไว้ และบอตแต่ละตัวสามารถเลือกโมเดลของตัวเองได้
สายที่สอง — Notion MCP
จากตาราง mcp_servers พบรายการ Notion MCP จำนวน 2 รายการ ทั้งคู่เป็นแบบ Streamable HTTP
เมื่อตรวจสอบการกำหนดสิทธิ์ พบว่าบอตทั้ง 77 ตัวได้รับสิทธิ์เข้าถึงข้อมูล Notion ในขอบเขตเดียวกัน ครอบคลุม 77 Pages และ Databases ที่กำหนดไว้
แต่สิทธิ์ระดับ Connection กับสิทธิ์การใช้เครื่องมือของบอตเป็นคนละชั้นกัน
แม้จะกำหนดขอบเขตข้อมูล Notion ไว้เหมือนกัน บอตแต่ละตัวยังสามารถถูกจำกัดการใช้เครื่องมือในโครงสร้างของตัวเองได้ เช่น การเปิดหรือปิดเครื่องมือบางตัวตามหน้าที่ของบอต
พูดง่าย ๆ คือ การมีสิทธิ์เข้าถึง MCP ไม่ได้หมายความว่าทุกบอตต้องใช้เครื่องมือทุกตัวเหมือนกัน
เมื่อตรวจละเอียดขึ้น ยังพบว่า Notion MCP ถูกลงทะเบียนไว้สองรายการ โดยใช้ชื่อเดียวกันและเปิดเครื่องมือชุดเดียวกัน
อาจเกิดจากการตั้งค่าซ้ำ แต่ยังไม่ควรลบรายการใดออกทันที จนกว่าจะตรวจสอบว่าแต่ละรายการมี Credential, Configuration หรือบอตที่อ้างอิงอยู่แตกต่างกันหรือไม่
.
## มีอีกหนึ่งสายที่ทำงาน แต่ไม่ได้อยู่ใน Integration
นอกจากสอง Integration ข้างต้น ยังมี Git ที่บอตใช้ทำงานกับ Repository โดยตรง
บอตใช้ Credential ที่เก็บไว้ใน Home Directory ของตัวเองบน Bot Computer แล้ว Push งานเข้า Repository
เส้นทางนี้ไม่ได้ถูกลงทะเบียนอยู่ในระบบ Integration ที่ตรวจสอบข้างต้น
จึงต้องแยกออกจากสอง Integration หลัก ไม่เช่นนั้นตัวเลขที่รายงานจะปะปนระหว่างการเชื่อมต่อผ่านระบบของ Rakazo กับการทำงานผ่าน Credential ของสภาพแวดล้อมที่บอตใช้งาน
.
## ชั้นที่ยังไม่ได้เปิดใช้งาน
จากการตรวจสอบตาราง connections พบว่ามีข้อมูล 0 แถว
หมายความว่ายังไม่มีแอปสำเร็จรูปที่ถูกเชื่อมต่อผ่านระบบ Connections บนเครื่องนี้ และ Key ของผู้ให้บริการ Catalog ก็ยังว่างอยู่ในไฟล์ตั้งค่า
ส่วนช่องทางแชตยังไม่มี Credential ของ Platform ใดถูกตั้งค่าไว้
ตอนนี้บอตจึงเข้าถึงได้ผ่านหน้าเว็บในเครือข่ายส่วนตัวของเครื่องเท่านั้น
นอกจากนี้ยังมีความสามารถอื่นที่เอกสารระบุว่ารองรับ แต่ยังไม่ได้ตั้งค่าใช้งาน ได้แก่
ส่วนระบบความจำภายนอกก็ยังไม่ได้เชื่อมต่อเช่นกัน
เอกสารระบุว่ารองรับการ Host Memory Server เองได้ 3 ตัวเลือก แต่บนเครื่องนี้ยังไม่มีการเชื่อมต่อ Memory Server เหล่านั้น
ปัจจุบันบอตมีเอกสารความจำในตัวอยู่ 9 เอกสาร
ตัวเลขนี้บอกเพียงสถานะของข้อมูลความจำที่ตรวจพบ ไม่ได้ยืนยันว่าความจำทั้ง 9 เอกสารถูกเรียกใช้หรือมีประสิทธิภาพในการทำงานมากน้อยแค่ไหน
.
## สิ่งที่เห็นจากการตรวจครั้งนี้
เมื่อแยกความสามารถตามเอกสารออกจากสถานะบนเครื่อง จะเห็นภาพชัดขึ้นว่า
Rakazo รองรับการเชื่อมต่อ 4 ชั้น แต่บนเครื่องของเรามี 2 Integration ที่ตั้งค่าไว้ คือ Model Endpoint และ Notion MCP
นอกเหนือจากนั้นยังมี Git ที่บอตใช้ Credential ของตัวเองเพื่อทำงานกับ Repository โดยตรง
ส่วนแอปสำเร็จรูป ช่องทางแชต และ Memory Server ภายนอก ยังไม่ได้เชื่อมต่อ
อีกสิ่งที่น่าสนใจคือ Notion MCP ไม่ได้มีแค่การเชื่อมต่อสำเร็จ แต่ยังมีการกำหนดขอบเขตข้อมูลที่บอตเข้าถึงได้ และมีการจำกัดเครื่องมือในระดับบอตอีกชั้นหนึ่ง
นี่ทำให้การตรวจสอบ Integration ไม่ควรหยุดแค่คำถามว่าเชื่อมต่อแล้วหรือยัง แต่ต้องดูด้วยว่าใครใช้ได้ ใช้ข้อมูลส่วนไหน และใช้เครื่องมืออะไรได้บ้าง
.
## #สรุปแบบวิศวกรเป็ด
ระบบรองรับ 4 ชั้น แต่เราไม่ได้จำเป็นต้องเปิดใช้ทุกชั้น
ตอนนี้มี 2 Integration ที่ตั้งค่าไว้ คือโมเดลบนเครื่องและ Notion MCP ส่วน Git เป็นอีกเส้นทางหนึ่งที่บอตใช้ Credential ของตัวเอง
สิ่งที่น่าสนใจไม่ใช่จำนวนแอปที่เชื่อมต่อได้ แต่เป็นการกำหนดขอบเขตให้บอตเข้าถึงเฉพาะข้อมูลและเครื่องมือที่จำเป็น
การเชื่อมต่อทุกอย่างไว้ก่อน อาจทำให้ระบบซับซ้อนขึ้นโดยที่ยังไม่มีงานรองรับ
ต่อสิ่งที่งานต้องใช้ ไม่ใช่ต่อทุกอย่างเพียงเพราะระบบเปิดช่องไว้
.
