# ZCode รีวิวหลังใช้ 125 วัน — งานทดสอบเว็บที่เคยกดเอง วันนี้ให้ agent ทำแทน

### จาก harness ที่ z.ai เขียนเองสำหรับ GLM-5.3 — รีวิวโดยใช้ของจริง ไม่ใช่อ่านเอกสาร

.

125 วัน — ระยะเวลาที่ใช้ ZCode ทำงาน ตั้งแต่ช่วงเปิดตัว

10,000 credits ต่อสัปดาห์ — เพดานของแผน Lite ที่ใช้อยู่

3 ช่องทาง — desktop app, มุมมองเว็บ, agent ใน terminal

.

## ก่อนจะรีวิว แยกชั้นข้อมูลให้ชัด

สิ่งที่ใช้เองตลอด 125 วัน — นับเป็นประสบการณ์ตรง

สิ่งที่เอกสารโปรเจกต์ระบุ — ยังไม่ผ่านการวัดอิสระ

ส่วน benchmark ฝั่งโมเดล — เป็นที่อ้างสิทธิ์ของผู้ผลิต ไม่ใช่ข้อสรุป

.

> **คำถามที่แท้จริงของโพสต์นี้คือ: งานทดสอบเว็บแบบมือ — วันนี้เหลืออะไรให้ทำเอง และเวลาที่ได้คืนไป คุ้มกับการเปลี่ยนวิธีทำงานไหม**

.

## เหตุการณ์หลัก: ทดสอบเว็บโดยใช้ GLM แทนมือ

แบบเดิม ทดสอบด้วยมือ เปิดหน้า กดไล่ทีละจุด เห็นภาพเดียวของหน้านั้นในวินาทีนั้น พอแก้อะไร ก็ต้องกดใหม่ทั้งรอบ

สิ่งที่ใช้อยู่ คือให้ GLM ทำแทนชุดเดิมนี้ — performance, UX/UI, SEO, AEO, ช่องโหว่ของเว็บ

มันกดเดินหน้าเว็บเหมือนมีคนนั่งกดอยู่จริง ๆ แล้ว capture หน้าจอใหม่ทุกจุดที่ผ่าน หรือดึงข้อมูลจากหน้าต่างที่ต้องการมาให้ดู

จบรอบมีรายงานสรุปให้เรียบร้อย พร้อมจุดที่ควรแก้ — และเลือกได้ว่าจะให้สรุปเป็นสาย tech สำหรับทีมจัดการต่อ หรือ non-tech สำหรับเจ้าของงานอ่านเข้าใจ

คนตัดสินยังเป็นคนเดิม แต่มือที่กดไม่ใช่มือเราอีกแล้ว — งานที่เหลือคืออ่านรายงาน แล้วสั่งแก้ต่อ

.

## Goal Mode — สามชั้นจากเอกสาร และสิ่งที่เจอข้างหลัง

จากเอกสารโปรเจกต์ Goal Mode ออกแบบมาเป็นสามชั้น

ชั้นแรก งานถูกปั้นเป็นรอบ แต่ละรอบจบด้วยการตรวจแยกต่างหาก

ชั้นสอง บังคับหลักฐาน ต้องเป็นไฟล์ที่ถูกแก้ ผลรันคำสั่ง ผลเทสต์ แผนงานหรือประโยคสรุปลอยไม่นับ

ชั้นสาม งบของ goal หมดเมื่อไหร่ มันหยุดเอง ไม่กิน quota แบบเงียบ ๆ

สิ่งที่เจอข้างหลัง ในงานที่ใช้มา ยังไม่เจอกรณีปล่อยงานจบเทียมผ่านรอบตรวจ — และงบหมดแล้วหยุดเอง ไม่ต้องไล่ตามปิด

ส่วนโมเดลถูกเทรนด้วย RL สำหรับงาน agent ยาว พร้อมกลไกกันหาทางลัด — ทางทีมระบุ ยังไม่มีการวัดอิสระมายืนยัน

.

## สิ่งที่เว้นได้หลังใช้มา และสิ่งที่มาจากเอกสาร

**จากการใช้เอง** — ชุดทดสอบเว็บข้างบน กับการสั่งและเสริมงานผ่าน Telegram ระหว่างวัน งานยาวไม่ต้องนั่งเฝ้า

**จากเอกสารและข้อมูลตลาด** — credits ของแผนใช้ข้าม agent อื่นได้กว่า 20 ตัว รวม Claude Code ลดความเสี่ยงติดขา

อีกจุดที่เจอบ่อยจนกลายเป็นปกติ — แจก token ฟรีให้บ่อยมาก

.


## ข้อจำกัดที่เจอ และข้อที่ยังไม่รู้

ส่วนที่ใช้เป็นประจำมีแค่ browser, Goal Mode, การสั่งระยะไกล — ระบบรอบตัวที่เหลือ (subagents, hooks, automations, wiki memory) ยังไม่แตะ กับคนที่งานสั้น ชุดนี้หนักเปล่า

Goal Mode ใช้คู่กับ execution mode อื่นไม่ได้ทุกแบบ (ขัดกับ Plan mode ตาม docs) เลือกโหมดก่อนตั้งเป้า

license ของ repo ตรวจที่ repo ก่อนอ้างว่าโอเพนซอร์สแบบไหน

ความเร็วและความนิ่งบนงานหนัก — ยังไม่มีข้อมูลพอสรุป ทั้งจากการใช้และจากแหล่งอื่น

.

## ควรใช้ไหม

**ใช่ ถ้า** — มีงานเว็บต้องตรวจซ้ำ ๆ (performance, UX/UI, SEO, AEO, ช่องโหว่) งานมีเป้าพูดจบประโยคเดียวแต่ต้องทำหลายรอบ และอยากสั่งเสริมจากมือถือ

**เลี่ยง ถ้า** — งานสั้นจบในรอบเดียว (โหมดปกติพอ Goal Mode ใช้ไม่ถึง) ยังต้องการ benchmark อิสระก่อนตัดสินใจ หรือจะอ้าง license — เช็คที่ต้นทางวันตัดสินใจ

.

## บทสรุปจากพร

สิ่งที่ ZCode ทำ ไม่ใช่ทำให้โมเดลเก่งขึ้น แต่คือจัดงานให้โมเดลทำได้ยาวโดยมีจุดตรวจ

ความคาดหวังส่วนตัว คือการตรวจงานด้วยหลักฐานและรายงานแบบนี้จะกลายเป็นของมาตรฐานของ harness — ยังไม่มีข้อมูลพอฟันธง แต่หลังใช้มาสามเดือนกว่า มันยากที่จะย้อนกลับไปทดสอบด้วยมือทั้งหมดอีก

**โมเดลเดี่ยวเคยเป็นสินค้า — วันนี้คู่ (model × harness) ต่างหากที่เป็นสินค้า**

.

บทนี้เล่าแค่ชั้นของเครื่องมือ

125 วันนี้มาได้อย่างไร แลกมาด้วยอะไร — เป็นเรื่องของอีกบท ยังไม่เล่าวันนี้

.
