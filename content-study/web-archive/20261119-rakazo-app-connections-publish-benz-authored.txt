เบ้น DNA ตรวจเอกสาร Rakazo และเอกสาร Notion ภายนอกแล้วครับ

**ความเข้าใจของคุณถูกในภาพรวม แต่มีจุดที่ต้องแยกให้ชัด: สิทธิ์เข้าถึง MCP กับสิทธิ์ของบอตในการเรียกใช้ MCP ไม่ใช่สิ่งเดียวกัน**

เอกสาร Rakazo ระบุว่า MCP Server สามารถกำหนดได้ว่าให้บอตตัวไหนใช้งาน โดยเข้าไปที่ Integrations แล้วเลือก **Use in this bot** และยังสามารถปิดเครื่องมือบางตัวเป็นรายบอตได้จาก Bot Settings → Advanced → Tools → Disable a tool&#x20;

ดังนั้น ภาพที่น่าจะตรงกับระบบของคุณคือ:

- Notion MCP มีขอบเขตข้อมูลที่อนุญาตไว้ 77 Pages และ Databases
- บอตทั้ง 77 ตัวได้รับสิทธิ์ใช้ MCP ในระดับเดียวกัน
- แต่ละบอตยังถูกกำหนดได้ว่าจะเปิดหรือปิดเครื่องมือใดในระดับตัวเอง
- การปิดเครื่องมือของบอตไม่ได้แปลว่าสิทธิ์ของ Notion Connection ถูกลดลงตามไปด้วย

**จุดที่ยังยืนยันไม่ได้จากเว็บไซต์:** ผมยังตรวจไม่ได้ว่าการตั้งค่าบนเครื่องของคุณกำหนด MCP ทั้งสองรายการให้บอตทั้ง 77 ตัวเหมือนกันจริงหรือไม่ และไม่มีการจำกัดเพิ่มเติมใน Custom MCP Server เอง

## **ข้อความที่ควรใช้ในบทความ**

สายที่สองคือ MCP — ตาราง `mcp_servers` มีสองรายการ ทั้งคู่เป็น Notion MCP แบบ Streamable HTTP

จากการตรวจสอบการกำหนดสิทธิ์ พบว่าบอตทั้ง 77 ตัวได้รับสิทธิ์เข้าถึง Notion ในขอบเขตเดียวกัน ครอบคลุม 77 Pages และ Databases ที่กำหนดไว้

อย่างไรก็ตาม สิทธิ์ระดับ Connection ไม่ได้หมายความว่าทุกบอตจะต้องใช้เครื่องมือทั้งหมดเหมือนกัน Rakazo ยังสามารถกำหนดได้ว่า MCP Server ใดเปิดให้บอตตัวไหนใช้ และสามารถปิดเครื่องมือบางตัวเป็นรายบอตได้อีกชั้นหนึ่ง

พูดง่าย ๆ คือ ขอบเขตข้อมูลที่ Notion อนุญาตเป็นชั้นหนึ่ง ส่วนการอนุญาตให้บอตเรียกใช้เครื่องมือเป็นอีกชั้นหนึ่ง

เมื่อตรวจละเอียดขึ้น ยังพบว่า Notion MCP ถูกลงทะเบียนไว้สองรายการ โดยใช้ชื่อเดียวกันและเปิดเครื่องมือชุดเดียวกัน อาจเกิดจากการตั้งค่าซ้ำ แต่ยังต้องตรวจสอบรายละเอียดก่อนรวมให้เหลือรายการเดียว

## **ข้อสรุปของเบ้น DNA**

ผมจะไม่ใช้คำว่า “บอต 77 ตัวอ่านเขียน Notion ได้ทั้งหมด” เพราะทำให้เข้าใจว่าเกิดการใช้งานจริงแล้ว

ใช้ว่า **“บอต 77 ตัวได้รับสิทธิ์เข้าถึงข้อมูล Notion ตามขอบเขตที่กำหนด”** จะแม่นกว่า

และนี่เป็นประเด็นที่น่าสนใจในบทความ: ระบบมีการแบ่งสิทธิ์เป็นหลายชั้น ไม่ใช่แค่เชื่อมต่อ Notion แล้วทุกบอตทำอะไรก็ได้

สิ่งที่ควรตรวจเพิ่มก่อนเผยแพร่ คือรายละเอียดของ MCP ทั้งสองรายการว่าผูกกับ Credential และขอบเขตข้อมูลเดียวกันจริงหรือไม่ เพราะนั่นจะทำให้ข้อสรุปเรื่องรายการซ้ำมีน้ำหนักมากขึ้นครับ
