# ZCode ผ่านมือ 125 วัน — คนตัดสินยังเป็นคนเดิม แต่มือที่กดไม่ใช่มือเราอีกแล้ว

### รีวิวจากการใช้งานจริงของ ZCode — Harness ที่ [z.ai](http://z.ai) เขียนเองสำหรับ GLM-5.3

.

125 วัน — ระยะเวลาที่ใช้ ZCode ทำงาน ตั้งแต่ช่วงเปิดตัว

3 ช่องทาง — desktop app, มุมมองเว็บ, agent ใน terminal

.

ก่อนอ่าน ขอแยกข้อมูลในบทนี้ออกเป็นสามชั้น

**ประสบการณ์ตรง** — สิ่งที่ใช้เองตลอด 125 วัน

**จากเอกสารโปรเจกต์** — สิ่งที่ทีมระบุ ยังไม่ผ่านการวัดอิสระ

**ความเห็นส่วนตัว** — ข้อสรุปจากการใช้งาน ซึ่งไม่ใช่ข้อเท็จจริงทั่วไป

.

> **สิ่งที่ ZCode เปลี่ยน ไม่ใช่การเอาคนออกจากกระบวนการ แต่เอาคนออกจากขั้นตอนที่ไม่จำเป็นต้องลงมือเอง**

.

## ก่อนใช้ ZCode

งานทดสอบเว็บไซต์แบบเดิมต้องผ่านมือแทบทุกขั้น

เปิดหน้าเว็บ กดตรวจทีละจุด เก็บหลักฐานทีละภาพ ไล่ดูผลด้วยตัวเอง แล้วสรุปว่ามีอะไรต้องแก้

พอแก้แล้วก็ต้องกลับไปทดสอบใหม่

งานหนึ่งรอบจึงไม่ได้มีแค่การตรวจ แต่มีการลงมือซ้ำ ๆ อยู่ตลอดกระบวนการ

.

## หลังใช้ ZCode

ตอนนี้ชุดทดสอบเดิม ให้ Agent รับช่วงการลงมือแทน

มันเปิดและเดินหน้าเว็บไซต์เหมือนมีคนนั่งกดอยู่จริง Capture หน้าจอในจุดที่ผ่าน และดึงข้อมูลจากหน้าที่ต้องการมาให้ตรวจสอบ

เมื่อจบรอบ มีรายงานสรุปพร้อมจุดที่ควรแก้

งานที่ Agent ช่วยตรวจได้ เช่น

- **Performance** — ค่าประสิทธิภาพที่วัดออกมาเป็นตัวเลข
- **SEO** — โครงสร้างที่ตรวจสอบเป็นรายการได้
- **UX/UI** — ส่วนที่ประเมินจากภาพและพฤติกรรมของหน้าจอ
- **AEO** — ส่วนที่เกี่ยวกับโครงสร้างข้อมูล

แต่ไม่ใช่ทุกอย่างที่ Agent รายงานจะถือเป็นข้อสรุปสุดท้าย

ถ้ารายงานชี้ว่าอาจมีช่องโหว่ นั่นคือจุดตั้งต้นให้คนตรวจสอบต่อ ไม่ใช่คำยืนยันว่าพบช่องโหว่จริง

UX/UI ในส่วนที่เกี่ยวกับความรู้สึกและประสบการณ์ใช้งาน ก็ยังต้องอาศัยคนพิจารณา

Agent รับการลงมือ ไม่ได้รับการตัดสิน

.

## สิ่งที่ยังเป็นของคุณ

สิ่งที่เปลี่ยนไปคือวิธีลงมือ ไม่ใช่คนที่รับผิดชอบผลลัพธ์

คุณยังเป็นคนกำหนดว่าจะทดสอบอะไร

ยังเป็นคนอ่านรางาน ตรวจสอบจุดที่ Agent ชี้ และตัดสินใจว่าจะให้แก้ไขอะไรต่อ

งานที่เคยต้องใช้มือเปิดเว็บ กดตรวจ เก็บภาพ และรวบรวมข้อมูล ตอนนี้ให้ Agent รับช่วงได้มากขึ้น

แต่การพิจารณาว่าผลที่ได้ถูกต้องหรือไม่ และควรทำอะไรต่อ ยังอยู่ที่คน

**คนตัดสินยังเป็นคนเดิม แต่มือที่กดไม่ใช่มือเราอีกแล้ว**

.

## Goal Mode — กลไกจากเอกสาร และสิ่งที่เจอจากการใช้

จากเอกสารโปรเจกต์ Goal Mode ช่วยให้งานระยะยาวมีองค์ประกอบสำคัญสามอย่าง

**เป้าหมาย** — งานถูกแบ่งเป็นรอบ แต่ละรอบจบด้วยการตรวจแยกต่างหาก

**หลักฐาน** — ต้องมีสิ่งที่ตรวจสอบได้ เช่น ไฟล์ที่ถูกแก้ ผลรันคำสั่ง หรือผลทดสอบ แผนงานหรือประโยคสรุปเพียงอย่างเดียวไม่นับเป็นหลักฐาน

**ขอบเขต** — มีงบสำหรับ Goal เมื่อใช้งบหมด ระบบจะหยุดทำงาน

ส่วนสิ่งที่พบจากการใช้งานของเรา คือยังไม่เจอกรณีที่งานจบเทียมแล้วผ่านรอบตรวจ และเมื่อใช้งบหมด ระบบก็หยุดตามขอบเขตที่กำหนด

นี่เป็นสิ่งที่พบจากงานที่ใช้จริง ไม่ใช่การรับรองว่าระบบไม่มีทางพลาด

.

## ผลลัพธ์ที่เปลี่ยนไป

ภาระที่ลดลงคือการลงมือเปิดหน้า กดตรวจ เก็บหลักฐาน และไล่รวบรวมข้อมูล

แต่สิ่งที่ยังอยู่ครบคือการกำหนดเป้าหมาย อ่านผล ตรวจสอบความถูกต้อง และตัดสินใจแก้ไข

ไม่มีตัวเลขประหยัดเวลาให้อ้าง เพราะยังไม่ได้วัด

แต่จังหวะการทำงานเปลี่ยนไปอย่างชัดเจน

จากเดิมที่งานทดสอบเว็บไซต์เริ่มด้วยการเปิดหน้าเว็บแล้วลงมือเอง วันนี้มันเริ่มด้วยการเขียนเป้าหมายให้ Agent ทำงาน

นอกจาก Browser และ Goal Mode แล้ว ยังใช้การสั่งงานผ่าน Telegram เพื่อสั่งเสริมหรือติดตามงานระหว่างวันได้ด้วย งานที่กำลังดำเนินอยู่จึงไม่จำเป็นต้องนั่งเฝ้าหน้าจอตลอดเวลา

อย่างไรก็ตาม การสั่งงานผ่าน Telegram ไม่ได้แทนการกลับมาดูผลและตัดสินใจบนจอหลัก

.

## ข้อจำกัดจากการใช้งานจริง

**Browser**

บางหน้าที่พึ่งพา Script หนัก ยังต้องกลับไปตรวจด้วยมือ

**Goal Mode**

เหมาะกับงานที่กำหนดเป้าหมายได้ชัดเจน หากเป็นงานสั้นหรือไม่มีเป้าหมายที่แน่นอน โหมดปกติอาจเพียงพอ

**Telegram**

เหมาะกับการสั่งเสริมหรือติดตามงานระหว่างวัน แต่การตัดสินใจสำคัญยังต้องกลับมาที่จอหลัก

.

## สิ่งที่ยังไม่มีข้อมูลยืนยัน

ความเร็วและความนิ่งในการทำงานบนงานหนัก ยังไม่มีข้อมูลเพียงพอให้สรุป

.

## บทสรุปจากพร

สิ่งที่ ZCode ทำ ไม่ใช่ทำให้โมเดลเก่งขึ้น แต่คือจัดกระบวนการให้โมเดลทำงานต่อเนื่องได้ โดยมีเป้าหมาย หลักฐาน และจุดตรวจสอบ

ประสบการณ์ 125 วันนี้ทำให้เห็นความแตกต่างระหว่างการใช้ AI ให้ทำงานแทน กับการใช้ AI ให้รับช่วงการลงมือ

อย่างแรกคือการปล่อยงานออกไป

แต่อย่างหลังคือการออกแบบให้ Agent ทำงานภายใต้เป้าหมายและเงื่อนไขที่เรากำหนด โดยเรายังตรวจสอบและตัดสินใจได้

**AI ที่ดีไม่ใช่ AI ที่ทำทุกอย่างแทนเรา แต่คือ AI ที่ทำงานได้มากขึ้น โดยที่เรายังเป็นคนกำหนดเป้าหมาย ตรวจสอบผล และตัดสินใจว่าจะไปต่อทางไหน**

Agent รับการลงมือ คนยังถือการตัดสินใจ

.
