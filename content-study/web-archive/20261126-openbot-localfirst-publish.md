# **OpenBot (openbot.run): ทีม AI ประจำเครื่องแบบ Local-first อ่านจากเอกสาร ยังไม่ได้ลองติดตั้ง**

สถานะบทความนี้: อ่านจากเอกสารทางการและ release notes ของ openbot.run ข้อมูล ณ 26 พ.ย. 2026 พรยังไม่ได้ติดตั้งใช้เอง ส่วนที่เป็นความเห็นพรจะบอกไว้ชัด

ก่อนอ่าน: พรไม่มีส่วนเกี่ยวข้องกับทีมผู้พัฒนา OpenBot และพรใช้ Rakazo ซึ่งเป็นเครื่องมือประเภทเดียวกัน พรมีอคติของตัวเองอยู่แล้ว บทความเทียบ 3 ตัวอยู่ที่ลิงก์ในคอมเมนต์นะค้าบ

.

## **ปัญหาที่มันพยายามแก้**

พรเจอเอง และหลายคนที่ใช้ AI ทำงานประจำวันน่าจะเจอเหมือนกัน

เปิดแชตทีละบอท ถามโค้ดในแท็บหนึ่ง ค้นคว้าอีกแท็บหนึ่ง แล้วตัวเองกลายเป็นคนก๊อปคำตอบข้ามหน้าต่างไปมา

พองานยาวขึ้น บริบทของห้องแชตเดิมก็หลุด บอทเริ่มลืมคำสั่งแรกๆ ที่ตกลงกันไว้

พรคิดว่าปัญหาไม่ได้อยู่ที่โมเดลฉลาดไม่พอ แต่อยู่ที่โครงสร้างการทำงาน การยัดงานหลายสเต็ปใส่หน้าต่างแชตเดียวคือการฝืนธรรมชาติของงานระบบ (นี่คือความเห็นของพร)

.

## **OpenBot คืออะไร (ตามเอกสาร)**

OpenBot พัฒนาโดย Synthetify Labs แจกจ่ายภายใต้สัญญาอนุญาต PolyForm Noncommercial 1.0.0 เป็น Local-first Desktop Multi-Agent Workspace

แนวคิดหลักคือสร้าง AI Agent เฉพาะทางหลายตัวไว้ในที่เดียว แทนบอทตัวเดียวทำทุกอย่าง Agent วิจัย Agent สถาปนิกซอฟต์แวร์ และ Agent พิสูจน์อักษรแยกจากกัน แต่ละตัวมีคำสั่งและบริบทของตัวเอง

และรองรับ Agent Handoffs เช่น บอทวิจัยเสร็จแล้วส่งงานต่อให้บอทเขียนโค้ด โดยไม่ต้องยัดบริบทเดิมทั้งหมดไปด้วย

.

## **Local-first แปลว่าอะไรจริงๆ**

หลายคนเข้าใจว่า Local-first คือออฟไลน์ 100% ตามเอกสารมันแบ่งเป็น 2 ชั้น

ชั้นที่ 1: ประวัติการทำงาน workspace โครงสร้างโฟลเดอร์ ฐานข้อมูล และการตั้งค่า เก็บบนเครื่องเรา

ชั้นที่ 2: สมอง AI ยังวิ่งผ่านเครือข่าย OpenBot ใช้รูปแบบ Bring Your Own Subscription ต่อกับบัญชีโมเดลที่เรามีอยู่ เช่น ChatGPT Plus สำหรับ Codex หรือ Claude Pro สำหรับ Claude Code

ข้อควรรู้: ทุกอย่างที่ Agent อ่านและส่งไปประมวลผล รวมถึงเนื้อหาในไฟล์ จะเดินทางไปที่เซิร์ฟเวอร์ของผู้ให้บริการโมเดล มันจะออฟไลน์สมบูรณ์ต่อเมื่อต่อ Local Model ผ่าน Ollama หรือ LM Studio

อีกเรื่องที่ควรเช็กก่อนใช้ คือเงื่อนไขของผู้ให้บริการแต่ละรายว่าอนุญาตให้ใช้แผนสมาชิกส่วนตัวผ่านเครื่องมือภายนอกหรือไม่ พรยังไม่ได้ตรวจเรื่องนี้

### **สิ่งที่น่าสนใจจากเอกสาร**

- โครงสร้างทีม Agent แยกบทบาท ซึ่งน่าจะลดการชนกันของบริบทระหว่างงาน (เป็นข้ออ้างของเอกสาร พรยังไม่ได้พิสูจน์)
- ประวัติงานอยู่บนเครื่อง ไม่ล็อกข้อมูลไว้กับระบบใคร
- มีเอกสารอธิบายทางต่อ Local Model ชัดเจน

### **สิ่งที่ต้องระวัง (จากเอกสารเดียวกัน)**

- สิทธิ์ Agent กว้าง หลังกดยินยอมครั้งแรก บอทอ่านเขียนไฟล์ รันคำสั่ง และควบคุมเบราว์เซอร์ได้โดยไม่ถามยืนยันทุกบรรทัด ห้ามชี้ workspace ไปที่โฟลเดอร์ข้อมูลสำคัญ และต้องสำรองข้อมูลก่อนเสมอ
- ติดตั้งไม่ใช่ปุ่มเดียวจบทุกเครื่อง เอกสารมีเรื่องยาวเกี่ยวกับ AppArmor ที่บล็อก Electron sandbox บน Linux รุ่นใหม่ และ Docker ที่ต้องปรับ seccomp กับ shm-size เอง
- ใช้ส่วนตัวฟรี ใช้เชิงพาณิชย์ต้องซื้อสิทธิ์แยกตามสัญญา PolyForm Noncommercial ถ้าคุณทำธุรกิจ ต้องอ่านข้อนี้ก่อนตัดสินใจ
- งานลับสูงควรต่อ Local Model เพราะคำสั่งของเรายังเดินทางออกไปประมวลผลนอกเครื่องอยู่ดี

.

## **วินัยที่ต้องมีถ้าจะใช้จริง**

อย่าดูแค่ข้อความสรุปสุดท้ายของ Agent เปิด Task Panel หรือ Activity Log ดูว่ามันเข้าไปแก้ไฟล์ไหน และรันคำสั่งอะไรลงเครื่อง

งานที่ AI สรุปว่าเสร็จ กับงานที่เสร็จจริง คนละเรื่องกัน

.
